# InGame 종이비행기 시제품

## 계열색 리소스를 실제 연구 웹에 연결

현재 InGame 연구 화면에는 계열색 PNG, 선택/강화 단계, 구매 피드백과 설명창을 연결했습니다. 실제 후보는 A1/G1/C1 세 종류이며 20개 전체 구조는 편집기 전용 미리보기로 제공됩니다. 최신 사용법과 검증 결과는 [연구 웹 적용 안내](RESEARCH_WEB_IMPLEMENTATION.md)를 참고합니다. 아래는 이전 변경 이력입니다.

## 참고 구조에 맞춘 연구 UI (2026-11-04, 11차)

다른 환경에서 실제 참조 이미지 픽셀을 확인해 전달한 구조 설명을 기준으로 수정했다. 기존 약 2/3 폭의 원형 노드 웹과 열린 세로 구분 패널에서, **왼쪽 약 75% 연구 웹 + 오른쪽 약 25% 높이 전체 테두리 패널**로 변경했다. 중앙 종이비행기 시작 노드는 화면 (36.5%, 52.5%)에 둔 정사각형이다. 입문 연구도 정사각형이며 직선과 45도 꺾임으로 연결한다. 던지기 A1은 좌상단, 조종 C1은 좌하단, 활공 G1은 우상단에 비대칭으로 배치했다. 내구 S1은 현재 구현되지 않았으므로 우하단 가지와 노드를 그리지 않는다. 미해금 고급/전문화 노드나 가짜 후보도 노출하지 않는다.

웹 내부에는 심볼·단계 점만 있고 글자는 없다. 선택은 이중 사각 테두리, 구매한 노드는 오른쪽 위 작은 체크로 표시한다. 오른쪽 패널에는 이름/단계, 옅은 파스텔 기체 그림, 효과 행, 구분선, 설명, 가격과 하단 구매 버튼을 배치했다. 상단은 연구점, 비행기 로고/제목, 비행/연구 탭, 톱니 아이콘을 두었다. 현재 별도 게임 설정 기능이 없으므로 톱니는 실제 지원하는 조작 안내를 열고 닫는다. 하단에는 구분선, 상태 범례와 큰 비행 복귀 버튼이 있다. 색감은 흰 바탕·검은 선 중심이며 비행기 그림만 옅은 민트를 사용한다. 구매·저장·비행 규칙은 변경하지 않았다.

Unity 6000.5.3f1에서 변경 UI 코드 컴파일 및 기존 연구·저장·비행 자동 검사를 다시 통과했다. 원본 코드의 레이아웃 비율·좌표·표시 조건을 확인했다. 실제 시각 검증을 위해 격리 복사본에만 자동 캡처 코드를 추가해 전용 Windows 플레이어를 빌드했고, 사용자 진행 데이터와 다른 파일로 연구 화면을 열었다. Direct3D 12에서는 캡처가 실패했으며, Direct3D 11과 단일 스레드 렌더 시도에서는 1600×900 PNG가 생성됐으나 직접 확인한 픽셀은 검은 화면뿐이었다. 따라서 실제 UI의 글꼴·잘림·원본 이미지와의 픽셀 비교는 아직 검증하지 못했다. Computer use는 사용하지 않았고 캡처용 코드·테스트 잔액·실행 파일은 원본 프로젝트에 넣지 않았다.

## 첫 연구와 반복 비행 (2026-11-04, 10차)

현재 InGame에는 시험비행 모드나 작업대 구분이 없으므로 **보상을 받는 공식 비행**으로 취급한다. 첫 착륙을 마치면 연구가 열린다. 0m 보상 비행도 완료했다면 해금된다. 비행 중에는 연구와 구매를 열 수 없다. 착륙 또는 다음 발사 대기 화면에서 **연구 열기 / U**, 연구 화면에서는 **닫기 / Esc**를 사용한다. 웹에는 심볼과 단계 점만 표시하고, 선택한 노드의 이름·설명·현재 효과·가격·구매 버튼은 오른쪽 패널에 표시한다. 흰 바탕, 검은 선, 민트/복숭아색 강조를 사용하며 현재 후보/구매한 세 노드만 보인다.

| 현재 ID | 연구 | 단계당 효과 | 단계별 가격 | 3단계 실제 값 |
|---|---|---|---|---|
| A1 | 던지기 강화 | 초기 속도 +3%, 합산 | 30 / 65 / 130 | 13 → 14.17m/s |
| G1 | 활공 연습 | 기본 침하 -4%, 합산 | 30 / 65 / 130 | 0.16 → 0.1408m/s |
| C1 | 조종 반응 | 상승 기수 및 이동 방향 반응률 +5%, 합산 | 30 / 65 / 130 | 기수 90 → 103.5°/s, 이동 방향 10 → 11.5/s |

S1 기체 내구는 HP와 장애물 피해가 없는 현재 게임에서 효과가 없으므로 구현·표시하지 않았다. HP 숫자만 만드는 대신 이후 피해 모델과 함께 추가한다. 기존 설계 문서의 C1(속도), C2(반응), M1(내구) 명칭보다 이번 사용자 요청의 A1/G1/C1/S1 명칭과 가격을 우선했다. 최대 상승각 +22°, 해제/소진 후 3초에 걸친 -24° 하강, 발사 입력 분리와 기존 에너지 모델은 유지한다. 연구는 기본 설정의 복사본에만 적용하며 비행 중 스냅샷은 바뀌지 않는다. 대기 중 구매는 즉시 다음 발사에, 착륙 후 구매는 재시작한 비행에 적용된다.

보상은 **floor(해당 비행의 최대 전방 거리 / 5m)**이며 runId별 한 번만 착륙 시 정산한다. 최고 기록을 매번 재사용하거나 누적 이동 경로를 더하지 않는다. 구간 정의가 없으므로 최초 구간 +20은 지급하지 않고, 조각/초반 지원 보너스도 이번 최소 흐름에 추가하지 않았다. R로 비행을 중단하면 미정산 보상은 버린다. 종료·강제 종료된 진행 중 비행은 다음 실행 시 발사 대기로 돌아오며 자동 보상을 지급하지 않는다. 비행 도중 위치를 복원하는 기능은 이번 범위에 없다.

재화·단계·완료 횟수·최고 기록·발사/정산 번호는 `Application.persistentDataPath/starter-research-v1.json`에 저장한다. 임시 파일 작성 후 원본을 교체하고 이전 정상본은 `.bak`에 보존한다. 비용 차감과 단계 상승, 보상과 정산 완료 표시는 각각 하나의 저장으로 처리한다. 저장 실패 시 메모리 상태와 잔액을 변경하지 않는다. 착륙 보상 저장 실패 때에는 재시작을 막고 재시도 버튼을 표시한다. 손상된 파일은 자동 덮어쓰지 않고 읽기 오류를 표시한다. 연구 열기·노드 선택·구매·닫기 클릭과 눌린 채 남은 마우스 입력은 발사로 전달되지 않는다.

새 런타임 파일 `FlightResearch.cs`에 연구/저장과 비행 세션을 구현했다. `FlightModel`은 설정 복사와 저장된 최고 거리 전달만 추가해 물리 계산을 보존했다. 검사는 사용자 저장 파일과 분리한 임시 파일로 수행하며 자동 Play의 95점 초기 잔액은 테스트 전용이다. 일반 게임의 초기 연구점은 0이다.

Unity 6000.5.3f1 격리 복사본에서 컴파일·모델·저장 씬·자동 Play 검사를 통과했다. 보상 내림 경계(149.99m=29점, 5m=1점), 첫 비행 해금, 부족/정확한 잔액, 30/65/130 비용, 각 3단계 한도, 잘못된 ID, 활성 비행 구매 금지, 저장 실패 원자성, 보상 저장 재시도, 파일 저장/재로드, 중복 runId·중도 포기 무보상, 손상 파일 보존을 검사했다. 각 연구의 실제 비행 효과와 최대 강화 3종 조합의 4개 입력 패턴 × 3개 시간 단계에서 에너지 감소·최종 착륙도 통과했다. 자동 Play에서 53.71m 착륙 보상 10점, 첫 해금, 연구 화면 입력 차단, 세 종류 각 1단계 구매/저장, 잔액 부족 거부, 재시작 속도 13.39m/s 및 재발사를 확인했다. 자동 Play 구매 검사는 UI가 호출하는 같은 구매 메서드와 가상 마우스 입력 차단 경로를 사용하며, 실제 화면 버튼의 시각 위치를 눌러 본 검사는 아니다.

첨부 UI 참고 이미지는 공식 Library 전송 도구가 Windows의 확장 속성 기록을 지원하지 않아 로컬 파일 설치에 실패했다. 한 번 재시도했지만 픽셀을 확인할 수 없었으므로 참조 이미지 구조와 일치한다고 주장하지 않는다. 이번 UI는 기존 기획의 중앙 연결형 웹과 최신 심볼 전용 요청을 따른 최소 구현이다. Unity 배치 실행의 자동 스크린샷도 파일을 생성하지 않아 실제 배치·글꼴의 시각 검증은 완료하지 못했다. Computer use와 실행 파일 재빌드는 하지 않았다. 아래 1~9차 항목은 이전 구현 기록이다.

## 해제·상승 여유 소진 시 관성 활공 (2026-11-04, 9차)

기존에는 상승 여유가 소진되면 `Recovery Pitch Response` 60°/s로 -10°를 향하고, 실제 이동 방향도 기수 각도로 즉시 정해져 갑자기 꺾이는 느낌이 있었다. 이 별도 소진 회전 분기를 없애고 **일반 클릭 해제와 소진 모두 현재 각도에서 3초 동안 SmoothStep으로 -24°까지 내려가는 같은 경로**를 사용한다. 소진 중 버튼을 놓아도 진행 중인 하강 타이머를 다시 시작하지 않는다. 속도가 충분히 회복되고 버튼을 놓아야 다시 상승할 수 있는 조건은 유지한다.

실제 이동 방향 `FlightPathPitch`를 기수 `Pitch`와 분리했다. `Flight Path Response` **10/s**의 지수 추종(시간 상수 약 0.1초)으로 움직이는 방향이 기수를 따라가므로 해제·소진 순간에도 직전 방향이 이어진다. 속도는 기존 운동/위치 에너지 교환으로 계산하며, 관성 효과가 에너지를 추가하지 않는다. 초기 속도 13m/s, 상승 기수 속도 90°/s, 최대 상승각 +22°, 중력·항력·침하·실속 속도는 유지한다. 기존 별도 `Recovery Pitch`와 `Recovery Pitch Response`는 제거했다. 재시작 시 이동 방향도 초기화한다.

CLIMB RESERVE가 0이라는 것은 속도 4m/s 아래로 내려가 상승에 쓸 운동 에너지 여유가 없다는 의미이며, 전체 비행 에너지가 0이라는 뜻은 아니다. 남아 있는 움직임을 즉시 버리지 않고 상승을 잠시 이어간 뒤 하강하여 속도를 회복한다. 전체 에너지는 항력과 침하로 계속 소모되고 착륙 시 정지한다.

Unity 6000.5.3f1 격리 복사본에서 컴파일·저장 씬 검사·자동 Play를 통과했다. 0.01/0.02/0.04초 단계에서 일반 해제와 상승 여유 0 직전/직후의 속도 벡터 및 실제 위치 변화로 계산한 속도·방향을 검사했다. 전환 후 0.4초까지 위로 이동하며, 3초 뒤 -24°와 하강 이동에 도달했다. 전환 중 속도 변화율은 8m/s² 미만, 방향 변화율은 45°/s 미만으로 제한된 범위에 있었고 속도가 0으로 꺼지지 않았다. 기본 0.02초 단계에서 소진 시작 속도 3.975m/s, 전환 중 최저 속도 2.800m/s, 최대 속도 벡터 변화율 1.214m/s²였다. 소진 후 버튼을 계속 누른 경우와 중간에 놓은 경우의 경로가 같음을 확인했다. 매우 작은 초기 에너지에서도 NaN·에너지 증가·무한 부유 없이 착륙했다.

기존 상승 반응(0.2초에 +18°), 발사 입력 분리, 점진적 하강, 반복 입력 에너지 감소, 착륙·재시작·재발사도 통과했다. 기본 0.02초 단계에서 2초 상승 후 여유 17.2%(이전 16.9%), 무입력 착륙 24.86m(이전 24.01m), 계속 누름 57.81m(이전 86.56m), 빠른 교대 103.49m, 주기 교대 80.64m였다. 계속 누르면 소진 후에도 최종 -24°로 하강하므로 이전 -10° 회복보다 착륙 거리가 짧아진다. 자동 Play 착륙은 53.71m였다. 화면 제어·직접 시각 검증·실행 파일 재빌드는 하지 않았다. 관성은 시제품의 운동 모델이며 완전한 Rigidbody 공기역학 모델은 아니다. 아래는 이전 변경 기록이다.

## 전진 속도 증가 (2026-11-04, 8차)

발사 속도 `Launch Speed`를 10 → **13m/s**로 30% 높였다. 회전 속도 90°/s, 최대 상승각 +22°, 해제 후 3초 동안 -24°로 내려가는 곡선, 실속 회복 속도 60°/s, 중력·항력·침하와 카메라 설정은 유지했다. 이동을 빠르게 하는 만큼 같은 각도에서 수직 이동도 빨라진다. 초기 에너지는 60.4 → 94.9J/kg로 증가하며, 발사 이후에는 기존 에너지 교환과 항력·침하 손실만 적용되어 입력으로 에너지가 생성되지 않는다. 아래 내용은 이전 변경 기록이다.

연구 구매·레벨·저장·비행 수치 연결은 아직 구현하지 않았다. 기획 문서의 '표면 정리'(항력 감소), '활공 연습'(침하 감소), '상승 조절'(상승 항력 감소), '손목 감각'(초기 속도 증가)은 추후 성장 경로이며, 이 시제품에서 구매하거나 효과를 적용할 수 없다.

저장된 InGame 씬에서 `Tools > FlyEditor > Verify Flight Balance`로 수식 및 가상 마우스 Play 검사를 실행할 수 있다. 테스트가 끝나면 편집 상태로 돌아오며 사용자의 Unity를 종료하지 않는다. 씬을 생성하거나 저장하지 않고, 저장하지 않은 씬 변경이 있으면 검사를 시작하지 않는다.

Unity 6000.5.3f1에서 검증한 결과: 손을 놓은 채 3초 뒤 26.00m 전진, 지면 여유 2.10m. 2초 상승 뒤 상승 여유 22.3%, 속도 5.89m/s, 중심 높이 5.81m. 무조작 활공은 약 56.50m, 계속 누르기는 약 55.6m, 빠른 교대는 약 57.8m, 1.25초 주기 교대는 약 60.8m였다. 발사 후 잠깐 상승하고 활공하는 실제 Play 테스트는 약 76.60m로 착지했다. 자동 검사는 발사 입력 분리·상승·활공·착지·재시작을 통과했고, 직접 클릭 후 손을 놓은 화면에서도 56.5m 착지를 확인했다. 0.01/0.02/0.04초 스텝에서 에너지 증가 없이 종료됨을 검사했다. 새 밸런스에 대한 Windows 실행 파일 재빌드는 하지 않았으며, 기존 실행 파일은 이전 수치일 수 있다.

Unity 6000.5.3f1 / URP 17.5 / Input System 1.19 / Windows PC.

## 바로 실행

`FlyEditor/Assets/_Project/Scenes/InGame.unity`를 열고 Unity의 Play 버튼을 누른다. 별도 씬 생성 메뉴나 설치 작업은 없다. 시작 화면에서 마우스 왼쪽 버튼을 클릭하면 발사된다.

| 입력 | 동작 |
|---|---|
| 대기 중 왼쪽 클릭 | 발사 |
| 발사 클릭을 놓은 뒤 왼쪽 버튼 유지 | 속도를 고도로 전환하여 상승 |
| 버튼 놓기 / 상승 여유 소진 | 직전 이동 방향을 이어가며 3초 동안 서서히 기수를 내려 활공·하강 |
| 비행 중 R | 현재 비행 보상을 버리고 초기 위치로 돌아가 발사 대기 |
| 착지 후 왼쪽 클릭 또는 R | 발사 대기로 돌아가기. 다음 클릭으로 재발사 |

발사 클릭을 계속 누르고 있어도 상승 입력으로 사용하지 않는다. 한 번 놓은 다음 눌러야 상승한다. 창이 포커스를 잃으면 조작을 해제하고, 돌아왔을 때도 버튼을 놓은 다음 다시 조작한다. 비행 거리는 전방 X축 이동 거리이며 완료된 비행의 최고 거리는 연구 진행과 함께 저장된다. 화면 고도는 기체 최하단과 지면 사이 거리다.

기존 Main 씬과 공유 Build Settings는 보존했다. 실제 폴더에는 InGame 씬이 없었으므로 새로 추가했다. 기존 Tools/FlyEditor 빌드 메뉴는 여전히 Main 대상으로 동작한다. 이 시제품 빌드는 아래 전용 배치 명령을 사용하거나 Build Profiles에서 InGame 씬을 선택한다.

## 구성과 조정

- `Scripts/Runtime/Gameplay/Flight/FlightModel.cs`: Ready → Flying → Landed → Ready FSM, 비행 계산, 기체 기하 구조.
- `PaperFlightController.cs`: Input System 마우스/키보드, FixedUpdate 비행 계산, 옆에서 따라가는 카메라, 종이비행기 메시·지면·파스텔 배경, HUD.
- `FlightResearch.cs`: 공식 비행 세션, 거리 보상과 중복 정산 방지, 세 연구 효과·구매, 원자적 파일 저장과 재로드.
- `Art/Shaders/PaperFlight.shader`: URP용 양면 무광 정점색 셰이더. 씬에서 직접 참조하여 빌드 포함을 보장한다.
- `Scripts/Editor/FlightVerification.cs`: 수식/FSM 검사, 가상 마우스를 이용한 별도 배치 Play Mode 검사, Windows 개발 빌드 진입점. 평상시 자동 실행하거나 씬을 생성하지 않는다.

InGame의 **Paper Flight Prototype** 오브젝트에서 Tuning 값을 조정한다. 초기값은 중심 높이 4m, 속도 13m/s, 중력 2.6m/s², 상승 22도, 최대 하강 -24도(해제 후 3초), 저속 회복 기준 4m/s다. 그래픽은 Play 시 이 오브젝트 아래에 생성된다. 다른 씬에 자동으로 생성되는 런타임 부트스트랩은 없다.

## 비행 에너지

질량당 기계적 에너지 `E = v² / 2 + g h`를 추적한다. 매 고정 스텝에서 기본 항력, 상승 조작 중 추가 항력, 수동 침하 손실을 먼저 빼고, 변경된 높이로부터 남은 속도를 계산한다. 상승은 운동 에너지를 소비하고, 하강은 위치 에너지를 회수한다. 입력 자체는 에너지를 추가하지 않는다. 최저 속도를 강제로 보장하지 않으며, 저속에서는 기수를 내려 회복한다. 속도 상한을 적용할 때도 초과 에너지를 버린다. 발사 대기 상태로 재설정할 때만 초기 에너지를 부여한다.

지면은 y=0의 평면이다. 같은 메시 꼭짓점을 사용해 피치 각도에서 가장 낮은 지점을 계산하고, 한 스텝 안의 접촉 시점까지 거리를 보간한 뒤 Landed로 전환한다. 이 시제품은 일반 Rigidbody 공기역학이나 복잡한 지형 충돌을 구현하지 않는다.

## 검증 명령

프로젝트를 다른 Unity 창에서 닫은 상태로 실행한다. `$project`는 저장소 안쪽의 Unity 프로젝트 폴더다. 검증은 프로젝트 밖 로그 경로를 지정할 수 있다.

```powershell
$unity = 'C:\Program Files\Unity\Hub\Editor\6000.5.3f1\Editor\Unity.exe'
$project = 'C:\Users\doun0\OneDrive\바탕 화면\File\GitHub\FlyEditor\FlyEditor'
& $unity -batchmode -force-d3d11 -projectPath $project -executeMethod FlyEditor.Editor.FlightVerification.Run -logFile flight-check.log
```

Play 검사는 비동기로 완료된 뒤 종료하므로 `-quit`를 붙이지 않는다. 성공 종료 코드는 0이며 로그에 `MODEL CHECKS PASSED`, `SAVED SCENE CHECKS PASSED`, `PLAY CHECKS PASSED`가 기록된다. 검사는 입력 장치와 입력 설정 복제본을 해당 배치 프로세스에서만 사용하며 종료 시 원래 설정을 복원한다.

Windows 시제품 빌드:

```powershell
& $unity -batchmode -quit -force-d3d11 -projectPath $project -executeMethod FlyEditor.Editor.FlightVerification.Build -flightBuild 'C:\Temp\PaperFlight\FlyEditor.exe' -logFile flight-build.log
```

검사 범위: 대기/발사/착지/재시작 전이, 발사 입력 분리, 상승·하강, 저속 회복, 에너지 단조 감소, 음수/NaN 방지, 0.01/0.02/0.04초 시간 간격, 연속 유지·해제·빠른 교대·주기 교대 입력. 최적화 효과에 대한 성능 측정이나 장기 밸런스 검증은 포함하지 않는다.
