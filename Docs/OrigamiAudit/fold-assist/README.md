# 종이접기 진행과 조작 보조

## 바뀐 조작

기본 두 점 접기는 그대로 사용합니다. 주머니를 펴거나 끝점을 들어 올리며 양옆을 함께 접고 싶을 때는 다음 순서로 진행합니다.

1. 움직일 끝점과 기준점을 찍습니다.
2. 오른쪽의 **양옆 점 찾기**를 누릅니다.
3. 제안된 네 점과 접힘 미리보기를 확인하고 면이나 끝점을 드래그합니다. 놓으면 적용됩니다.

버튼은 접기를 자동 확정하지 않습니다. 제안된 점을 다시 클릭해 해제·교체할 수 있고, 처음부터 `점 추가 [F]`로 직접 고를 수도 있습니다. 제안에 실패하면 처음 두 점을 유지합니다. 전체 겹 모드에서는 이 제안을 제공하지 않으며, 개별 영역을 고른 상태에서 사용합니다.

## 공통 계산

- 선택한 면과 실제 재료 접힘축을 공유하는 이웃 면의 모서리를 후보로 사용합니다. 화면에서 겹친다는 이유만으로 다른 겹을 후보에 섞지 않습니다.
- 첫 점과 기준점 양옆에서 후보를 최대 세 개씩 추립니다. 최대 아홉 조합만 확인하고, 최소 5도라도 접을 수 있는 조합을 제안합니다. 180도 완성을 보장하는 추천은 아닙니다.
- 화면에서 겹쳐 보이는 두 보조점도 원래 종이 좌표가 다르면 구분합니다. 닫힌 주머니를 눌러 펴는 기존 계산을 새 네 점 입력에 연결했습니다. 별도 모드나 추가 단축키를 만들지 않았습니다.
- 계산은 버튼을 누를 때만 수행합니다. 매 프레임 후보를 검색하지 않습니다. 실측 플레이 성능 향상을 주장하는 변경은 아닙니다.
- 제안을 적용할 때 기존 두 점 접기의 미리보기와 임시 회전 상태를 정리합니다. 새 접기 레시피에는 `exactSquash`가 기록되고, 이전 저장 레시피는 기존 계산으로 재생합니다.

## 백합 진행 상태

기존 19회 상태에서 두 번의 겹 넘기기를 진행해 **21회 상태**를 저장했습니다. `Tools > FlyEditor > Validation > Open lily study - INCOMPLETE (Play Mode)`에서 최신 상태를 열 수 있습니다. 기본 비행기나 사용자 저장 기체는 자동 교체하지 않습니다.

다음 꽃잎을 꺼내기 위한 준비 상태이며 **백합 완성품은 아닙니다.** 다음 꽃잎의 양옆 점을 펼치면 접기 계획은 생성되지만, 주변 고정 겹과의 충돌 때문에 양방향 모두 막히는 경우가 남아 있습니다. 180도 겹 넘기기와 90도 벌리기를 조합해 시도했고, 막힌 각도를 강제로 저장하거나 충돌 검사를 끄지는 않았습니다.

기존 19회 레시피는 `before-19.json`에 보관했습니다. 최신 레시피와 실제 작업대 캡처는 `../lily-study/partial.json`, `../lily-study/workbench-paper.png`에 있습니다.

## 검증 범위

- 닫힌 주머니 네 곳과 꽃잎 한 곳: 보조점 제안, 65개 각도 자세, 면적·재료 접합부, 저장 재생, 되돌리기.
- 동일 점·종이 밖 점 거절, 제안만으로 종이가 변하지 않는 조건.
- 작업대: 두 점 선택, 제안 콜백, 드래그 접기, 편집 취소, 밀착, 다음 선택, 네 번째 점 해제·재선택, 후속 변 맞추기.
- 입력 검사는 Unity Input System 이벤트로 점 선택·드래그를 수행합니다. 배치 모드에서는 해당 이벤트가 IMGUI 버튼 클릭을 생성하지 않아 **양옆 점 찾기 버튼의 동일 콜백을 직접 호출**합니다. 운영체제 마우스로 버튼을 클릭한 검사로 표기하지 않습니다.
- 21회 레시피: 저장 재생, 되돌리기, 중간 자세와 접합부 검사. 실제 Play Mode 작업대에서 열고 적용 없이 닫은 뒤 기체 및 연구 포인트가 유지되는지 확인합니다.
- 기존 접기 회귀 검사. 결과는 `validation.txt`에 남깁니다.

재실행 메뉴: `Tools > FlyEditor > Validation > Fold handle assistance`. 입력 검사는 별도 테스트 프로젝트에서 `-executeMethod FoldAssistInputPlay.Run`으로 실행합니다. 종료 시 해당 Unity Editor가 닫히므로 사용 중인 작업 Editor에서는 호출하지 않습니다.
