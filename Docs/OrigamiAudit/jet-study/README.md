# 첨부 전투기형 종이비행기 엔진 검증 — 미완성

2026-11-11. 꽃잎 완성을 우선하던 작업에서, 사용자가 첨부한 긴 기수·각진 날개·꺾인 날개 끝의 비행기를 접을 수 있는지를 개발 목표로 전환했다.

**첨부 기체를 완성했다는 뜻이 아니다.** 원본 도안의 모델명과 전체 겹 순서는 아직 확인되지 않았다. 압축된 사진에서 읽을 수 있는 형태 변환으로 시험 경로를 구성했다. 특히 전체 겹을 좁히는 선택과 후반 날개 접기 위치는 검증용 해석이며, 원본 제작법과 동일하다고 판정하지 않았다. 기체별 완성 메시나 숨겨진 보정 좌표를 런타임에 넣지 않았다.

## 이번 공통 엔진 수정

- 가장자리 두 점과 목표선 두 점으로 접을 때도 일반 접기와 같은 중립면 회전축, 충돌 검사, 평평해진 겹의 순서 계산을 사용한다.
- 예전 가장자리 맞춤은 두께만큼 축이 이동해 중간 각도에서 접합부가 벌어졌다. 기존 동작으로 재현하고 수정된 동작과 비교했다.
- 공유 꼭짓점의 첫 소유 면이 다른 각도로 기울어져 있어도, 선택한 면과 같은 좌표계를 가진 소유 면을 계속 찾는다. 기울어진 날개의 가장자리도 기준선에 맞출 수 있다.
- 기존 전체/개별 선택을 가장자리 맞춤에도 전달한다. 전체를 골랐는데 한 겹만 접히던 경로를 수정했다. 개별 모드의 다른 겹 충돌은 계속 유지한다.
- 미리보기와 확정에 `PaperSheet.TryPreviewTurn`을 함께 사용해 마지막 각도에서 계산 결과가 달라지지 않게 했다.
- 새 조작 모드나 단축키는 추가하지 않았다. 새 작업대 동작은 기존 `continuousHinge`, `neutralContacts` 저장 필드를 사용하며, 그 필드가 없는 예전 가장자리 맞춤 레시피는 종전 동작을 유지한다.

## 실제 엔진으로 저장된 시험 경로

| 행동 | 결과 | 원본 대응 판단 |
|---|---|---|
| 1 | 4점 모으기로 삼각 기본형 | 예비 접기 없이 기본 형태 구성 |
| 2–3 | 양쪽 가장자리를 중심선에 맞춰 마름모형 구성 | 도안의 기수 좁히기 참고 |
| 4–5 | 다시 양쪽 가장자리를 중심선에 맞춰 긴 기수 구성 | 선택 겹 수는 원본 확인 필요 |
| 6–7 | 외측 하단 플랩을 각각 뒤집음 | 후반 날개 꺼내기를 위한 시험 경로 |
| 8 | 동체 중앙을 반으로 접음 | 시험 경로 |
| 9 시도 | 주날개 펼치기 차단 | 완료하지 않음 |

9번째 시도는 현재 화면상의 바깥 면을 선택해도 해당 플랩의 다른 부분에 겹이 겹쳐 있다. 계획은 생성되지만 양방향 허용 각도는 0도다. `anchor=18`, `layer=35`, 이동 조각 2개/고정 조각 36개. 충돌 우회 없이 중단했다. 이는 이 시험 경로의 차단 결과이며, 원본 도안 자체가 접힐 수 없다는 뜻이 아니다.

다음 작업은 원본의 겹 순서를 확인하고, 날개를 구성하는 여러 겹의 묶음을 골라 여는 동작을 검증하는 것이다. 필요한 경우 기존 힌지를 먼저 여는 공통 준비 동작을 확장한다. 모든 겹을 임의로 동반 이동시키거나 충돌을 끄는 방식은 완료 기준에 포함하지 않는다.

## 검증

- `JetEdgeVerification`: 8가지 단일/겹침/기울어진 날개 사례, 368개 중간 자세. 기존 접합부 틈과 공유 점 선택 실패를 재현했다. 종이 면적, 모든 재질 접합부, 다른 겹 고정, 충돌 방향 차단, 부분/완전 저장 재생, 되돌리기를 검사한다.
- `JetStudyAudit`: 시험 경로 8행동의 488개 중간 자세에서 면적과 접합부를 검사하고, 단계마다 JSON 저장·재생을 검사한다.
- 추가 회귀 및 실제 입력 결과는 `validation.txt`에 기록한다. 이 검사는 해당 기체의 완성도나 실제 비행 성능 인증이 아니다.

## Unity에서 확인

플레이 모드에서 `Tools > FlyEditor > Validation > Open jet study - INCOMPLETE (Play Mode)`를 누른다. 8행동 시제품을 작업대에 연다. 작업대에서 사용자가 직접 적용하기 전까지 기존 저장 기체와 연구 포인트는 변경하지 않는다.

`partial.json`과 단계별 PNG는 공통 접기 엔진으로 생성한 실제 메시다. `reference.png`는 사용자가 제공한 참고 이미지다. 생성 이미지나 완성형 모델로 대체하지 않았다.
