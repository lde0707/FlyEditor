# 드래곤 접기 검증 · 미완성

**결과: 드래곤 완성 실패.** 새 정사각형 한 장에서 시작해 앞 꽃잎과 뒷면의 작은 삼각 주머니까지 실제 입력으로 만들었다. 도안 10~12의 작은 꽃잎은 완료하지 못했다. 이후 단계는 미검증이다.

[작성자 공개 도안](https://jonakashima.com.br/wp-content/uploads/2015/07/Dragon-Jo-Nakashima.pdf) · [모든 시도와 실수 기록](전체시도.md)

본 기록의 사진은 실행 중인 Unity 원본 캡처다. 점/면 선택 후 장면과 접은 결과를 각각 남겼다. 도안 1~2의 준비 주름은 직접 점을 지정하는 기존 조작으로 생략했다. 정사각형부터 수행한 세션 A 이후, 같은 종이의 체크포인트를 재시작해 이어 갔다. 사용자 게임 저장 파일은 덮어쓰지 않았다.

## 확인한 공통 오류와 수정

- 공유 변 양쪽 후보의 화면 거리가 같을 때 면 배열에서 먼저 저장된 쪽을 선택했다. B-002는 왼쪽 클릭인데 source.face=12(오른쪽), 같은 위치 아래 실제 보이는 면은 14였다.
- `NearestAlignmentEdge`에서 같은 위치의 후보라면 커서 아래 보이는 면을 우선하도록 수정했다. 면 번호·도안 단계에 따른 분기는 없다.
- 수정 전 테스트는 실패했고, 수정 후 좌우 12개 클릭 검사는 통과했다. 실제 입력 C에서도 source.face=14로 바로잡혔다.
- 경로 검색 실패 안내가 충돌이라고 단정하던 문구를, 실행 가능한 경로를 찾지 못했다는 정확한 안내로 바꿨다.

## 미완료 기술의 기록

**기대:** 작은 삼각 주머니의 자유 가장자리와 양옆 접힘을 지정하고, 선택한 윗겹을 들어 올리며 작은 꽃잎으로 전환한다. 주변 본체와 독립된 아랫겹은 보존해야 한다.

**관찰:** 받침 아래의 끝을 1번으로 고르면 재료 선택 다각형이 시작 면을 포함하지 않아 거부됐다. 자유 가장자리 중앙과 양옆 경계의 교차점을 다시 지정해도 실행 경로가 생성되지 않았다. 단순한 네 점 조합에서는 변 맞추기로 분류되는 경우도 있었다.

**확인한 내부 조건:** 최종 교차점 요청의 `PaperPetalFold.Create → CollectBacking`은 `upper=2, active=2`에서 양옆 받침 연결을 구성하지 못해 null을 반환했다. 일반 코너 솔버로 넘어가도 양 방향 5° 표본에서 Pose가 실패했다. 이것은 현재 솔버가 해당 선택을 처리하지 못한다는 증거이며, 이 네 점이 도안의 모든 준비 동작을 완전히 표현한다는 물리적 증명은 아니다.

**시도한 공통 개선:** 새 접힘 경계에서 계산용 면을 재료 좌표로 분할하는 후보를 만들었지만, 이 요청을 해결하지 못했다. 후보와 새로운 저장 필드는 모두 제거했다. 충돌 차단과 접합 검사를 우회하지 않았다. 이후의 준비 접기 대안 G도 도안 12 완성으로 인정하지 않았다.

**후속 엔진 과제:** 기존 이중 연 모양만 가정하는 꽃잎의 받침 그래프와, 중첩 삼각 주머니의 다중 접힘 그래프를 구분해야 한다. 선택된 현재 표면 패치에서 물질 접합을 추적하고, 새 접힘 경계·고정 영역·공동으로 움직이는 받침을 함께 구성하는 공통 계획이 필요하다. 임의의 겹을 덧붙이거나 원래 종이를 잘라 독립시키는 처리는 해법이 아니다.

## 재현 데이터

- `checkpoint-five.json`: 앞면 꽃잎까지 만든 상태. 공유 변 선택 테스트의 시작점.
- `checkpoint-seven.json`: 작은 삼각 주머니까지 만든 상태. 미완료 기술의 시작점.
- `small-petal.json`: 받침 아래 끝을 잘못 잡은 시도.
- `free-edge-petal.json`: 자유 가장자리 중심을 고른 시도.
- `intersection-petal.json`: 양옆 교차점을 고른 마지막 실패 요청.
- `session-a`~`session-g`: 단계별 선택/결과 캡처, 실제 입력, 레시피, 상태, 선택한 변 좌표.

각 세션의 좌표는 1280×900 작업대 기준이다. 확대/회전 후 화면 좌표가 변하므로, 캡처·카메라 정보·레시피를 함께 확인해야 한다.
