# 접기 엔진 개선: 연결된 반환 면과 입력 범위

## 실제로 재현한 막힘

1. **같은 모양인데 내부 면 분할에 따라 꽃잎이 접히지 않음.** 백합 연구의 첫 꽃잎 직전 형상을 삼각형 조각으로 더 나누면, 기존 계산은 접힘축에 바로 닿는 조각만 반환 면으로 찾았습니다. 이어진 조각이 누락되어 재료 접합부 검사가 0도에서 중단됐습니다.
2. **네 번째 점을 누르면 선택이 모두 사라짐.** 새 기본형의 처음 두 점이 같은 면에 속하면 면 제한이 설정됐고, 네 점 접기의 반대편 보조점도 그 면에서만 찾았습니다. 이웃 면의 보조점은 검출되지 않았고 빈 공간처럼 취급됐습니다. 수정 전 작업대 입력에서도 같은 실패를 재현했습니다.
3. **일반 접기와 기존 접힘 벌리기가 서로 다른 힌지 기준을 사용함.** 작업대의 두 점 접기는 연속 힌지를 사용했지만 꼭짓점/면으로 기존 힌지를 벌리는 경로는 이전 두께 오프셋 기준을 사용했습니다. 이번 변경은 벌리기도 동일한 중립면 기준으로 계산하도록 맞춥니다. 이 항목의 새 검사는 위치 보존 검사이며, 모든 기존 벌리기가 실패했다는 뜻은 아닙니다.

## 공통 처리 규칙

- 꽃잎의 반환 면은 원래 종이 좌표상의 공유 변을 따라 탐색합니다. 같은 평면·재료 변환·겹에 있는 이어진 조각을 함께 추적합니다. 화면에서 겹친다는 이유로 다른 겹을 합치지 않습니다.
- 반환 면의 실제 끝점을 연결된 조각 전체에서 찾아 부분 반환 면에도 같은 규칙을 적용합니다.
- 네 점을 고르는 동안에는 보이는 이웃 면의 보조점도 선택할 수 있습니다. 움직일 면의 선택 범위와 보조점의 선택 범위를 구분합니다. 네 번째 점을 고른다고 전체 겹 모드가 되지 않습니다.
- 종이는 클릭했지만 현재 선택 범위에서 점을 찾지 못했을 때는 선택 전체를 지우지 않습니다. 실제 빈 공간 클릭으로 선택을 해제하는 동작은 유지합니다.
- 새 두 점 접기와 꼭짓점/면 벌리기는 재료의 중립면을 축으로 회전하고 접촉을 판정합니다. 닫힘 끝점의 수치 오차는 관통과 구분합니다. 고정된 다른 겹으로 진입하는 방향은 계속 차단합니다.

## 저장 호환성 / 적용 범위

`connectedPetalBacking`은 새 레시피에 저장하는 선택적 플래그입니다. 기존 저장 레시피는 플래그가 없으므로 기존 계산으로 재생합니다. 새 작업대의 개별 영역 네 점 접기는 `connectedPetalBacking`, `partialPetalBacking`을 사용하며, 두 점 회전과 벌리기는 `continuousHinge`, `neutralContacts`, `compactLayers`를 사용합니다.

`exactSquash`는 여전히 연구용 레시피에서만 사용합니다. 기본 입력에 임의로 켜지 않았습니다. 접기 제한이나 비행 스탯, 사용자 저장 데이터는 변경하지 않았습니다.

## 검증 방법

- 4개 회전 방향 × 양옆 점 순서 2개: 8개 분할/비분할 꽃잎 비교, 15도 간격 104개 자세. 면적, 재료 접합부, 같은 재료 점의 위치, 반대 방향 차단, 각도 왕복을 검사합니다.
- 실제 레시피의 부분/완전 접기 저장·재생·되돌리기. 내부 분할 비교는 테스트용 형상이며 별도의 저장 레시피 완성 사례로 계산하지 않습니다.
- 7개 초기 각도 × 4개 축 방향: 28개 연속 힌지 벌리기와 저장·재생·되돌리기.
- 작업대 실제 입력: 네 점 선택 → 꽃잎 90도 → 편집 취소 → 밀착 180도 → 다음 선택 → 빈 공간 해제 → 되돌리기 → 다른 면의 네 번째 점 → 변 맞추기.
- 실제 작업대 겹 분리: 보이는 윗겹과 아랫겹을 반대 방향으로 접기, 숨은 겹 선택, 전체 겹 모드, 미선택 면의 재료 위치·경계 보존. 닫힘 후 겹 정렬은 불변 객체를 새로 만들 수 있어 객체 참조가 아닌 재료 좌표와 중립면 위치를 비교합니다.
- 기존 주머니, 꽃잎, 중첩 접기, 묶음 뒤집기, 비행기, 잡는 위치, 형상 스탯 회귀 검사.

검사 출력은 `validation.txt`에 기록합니다. 실제 렌더링 캡처는 `petal-open.png`, `next-edge-fold.png`, `opposite-wings.png`입니다.

재실행: Unity 메뉴 `Tools > FlyEditor > Validation > Connected fragments and opening`. 입력 검사는 별도 테스트용 Unity 프로젝트에서 `-executeMethod ConnectedFoldInputPlay.Run`으로 실행합니다. 이 검사는 실행한 Editor를 종료하므로 사용 중인 작업 Editor에서 호출하지 않습니다.

## 남아 있는 한계

백합은 여전히 **19회 접기까지 검증된 미완성 연구 상태**입니다. 이번에 개선한 것은 연결된 동일 패널의 누락과 입력 범위 문제입니다. 남은 꽃잎 세 곳의 직접 계획 생성은 아직 실패합니다. 여러 방향으로 꺾인 인접 패널과 이미 접은 꽃잎을 함께 벌려 다시 닫는 일반 다중 힌지 풀이까지 구현한 것은 아닙니다. 충돌을 끄거나 완성 메시를 넣어서 성공 처리하지 않았습니다.

이 검사는 모든 종이접기나 모든 유한 두께 자기 충돌의 정확성을 보증하지 않으며 실시간 성능 벤치마크도 아닙니다.
