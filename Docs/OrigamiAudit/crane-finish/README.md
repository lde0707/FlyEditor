# 학 재접기 개선 결과

- 검증 환경: Unity 6000.5.3f1, 실제 접기 엔진 및 작업대 입력.
- 최종 레시피: `crane.json`, 16회 접기. 완성 메시를 주입하지 않고 최초 정사각형부터 재생한다.
- 이미지: `crane-three-quarter.png`, `crane-back.png`, `crane-front.png`.

## 이번 수정

1. 되접기 꺾임선 각도를 접기 데이터에 저장한다. 기존 값 0은 기존 65도로 해석하여 이전 레시피를 유지한다. 작업대 R은 65도/115도 방향을 전환하며, 진행 중이면 미리보기를 0부터 다시 시작한다.
2. 이미 접힌 겉면의 좌표를 다른 면까지 연장해서 잘못된 접힘축으로 해석하던 문제를 수정했다. 전체 겹 되접기는 같은 위치를 공유하는 실제 면의 재료 좌표를 찾아 저장한다. 개별 면 접기의 범위를 전체 겹으로 바꾸지는 않는다.
3. 새 일반 접기는 종이 중립면의 경계를 회전축으로 쓴다. 두께만큼 밀린 축 때문에 부분 접기에서 실제 재료 경계가 벌어지던 문제를 수정했다. 이전 저장 데이터는 기존 축을 유지한다.
4. 학의 목·꼬리 시작점을 몸통 쪽으로 올리고, 목과 꼬리를 반대 방향으로 되접었다. 바깥 날개부터 펼쳐 두 날개가 서로 반대쪽으로 나오게 했다.

## 실제 재접기 순서

- 1–4: 모양을 만드는 대각 접기 2회, 앞뒤 주머니 눌러 펴기 2회.
- 5–6: 앞뒤 꽃잎 접기.
- 7–10: 목·꼬리 가장자리 좁히기.
- 11: 가운데 묶음 접기.
- 12–13: 목 65도, 꼬리 115도 꺾임선으로 각각 되접기. 재료 기준 목 시작점 (3.8,3.8), 꼬리 시작점 (7.2,7.2).
- 14: 목 안쪽에서 부리 되접기.
- 15–16: 바깥 날개 +90도, 반대 날개 -90도. 양 날개 끝 간격 약 6.44365 게임 종이 단위.

좌표와 도안 순서는 검증 레시피에만 있다. 런타임 엔진에는 학 이름이나 특정 좌표 분기가 없다.

## 검증

- 일반 되접기: 4방향 × 꺾임선 각도 4종 = 16개 경우. 앞뒤 스크럽, 부분/전체 저장 복원, 되돌리기, 잘못된 입력 거부.
- 연결 회전축: 4방향 × 각도 6종 = 24개 경우. 부분 접기의 실제 재료 경계 및 T자 연결 경계 유지.
- 학 16단계 각각 면적, 유한 좌표, 모든 재료 경계와 저장 복원 통과. 목·꼬리·부리 동작도 5도 간격으로 검사.
- 기존 주머니, 꽃잎, 4점, 겹 분리, 중첩 되접기, 비행기 도안 회귀 검사 통과.
- 실제 작업대 입력: 꼬리의 점 두 개 클릭 → R 반대 방향 → 드래그 전진/후진 → 적용, E 편집 → R 전환 → 취소, Z 되돌리기 통과.
- 실제 입력으로 만든 일반 부분 접기에 새 회전축이 적용되는 것 확인.

자동 검증 레시피로 16단계를 재생한 결과와 실제 마우스 입력 검증 범위는 위처럼 구분한다. 16단계를 모두 마우스로 처음부터 끝까지 조작한 검증은 아니다.

## Unity에서 확인

플레이 모드의 출발 대기 또는 종이접기 화면에서:

`Tools > FlyEditor > Validation > Open crane sample (Play Mode)`

레시피를 작업대에 재생한다. 작업대에서 '접은 기체 적용'을 누르기 전에는 저장된 기체를 바꾸지 않는다.

일반 회귀 검증 메뉴:

`Tools > FlyEditor > Validation > Reverse direction and continuous hinges`

## 남은 한계

- 지금 결과는 몸통이 납작한 학 형태다. 몸통을 부풀려 입체적인 마름모/피라미드로 만드는 과정까지 완료한 표준 학으로 판정하지 않았다.
- 더 낮은 날개 뿌리(4.25~5.25)는 연결된 면 또는 겹 간 충돌로 여전히 제한됐다. 이번 결과는 5.5 뿌리를 사용한다.
- 중립면 경계는 연결되지만, 여러 겹의 표시 두께는 아직 간격이 커 보이는 곳이 있다. 물리적인 두께 접촉까지 완벽하다는 의미는 아니다.
- 임의 도안 전체가 완성 가능해졌다고 주장하지 않는다.
