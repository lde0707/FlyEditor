# 종이접기 5종 검증 — 예비 접기를 생략한 게임 방식

2026-11-10 수정 · Unity 6000.5.3f1 · 한 변 13점 / 초기 169점

## 판단 기준 수정

**위치를 표시하려고 접었다 펴는 도안의 예비 접기는 플레이어에게 요구하지 않는다.** 게임에서는 점으로 위치를 지정해 바로 형상을 바꿀 수 있어야 한다. 필요한 접힘선과 움직일 면의 계산은 엔진의 책임이다.

이전 보고서는 실제 종이의 예비 접기를 그대로 수행했다. 그 과정의 펼치기 실패와 8회 소모를 게임의 핵심 장애물로 평가한 부분을 철회한다. 해당 실행 기록은 버그 조사 자료로 남기지만, 게임 방식의 제작 가능 여부를 판단하는 근거로 쓰지 않는다.

- 위치를 표시하기 위한 예비 접기: 생략.
- 완성 모양에 필요한 접기, 주머니 벌리기, 뒤집기: 실제 동작으로 검증.
- 판정: 지정한 위치를 기준으로 원하는 면만 움직여 도안의 목표 형상에 도달하는가.
- 단순히 변형 후보가 생성되거나 한 각도에서 움직이는 것은 작품 완성과 다르다.

## 현재 3점 입력의 상태

현재 `FoldingDesk.ShowThreePoints()`는 `RightFlank` 상태로 이동해 **네 번째 점을 기다린다**. 화면에도 `3점 · 한 점 더`를 표시한다. 따라서 독립적인 ‘3점 지정 후 바로 벌리기’가 이미 구현되어 있다고 설명하면 안 된다.

이번에는 진단 경로와 판단 기준을 수정했다. 실제 3점 벌리기 입력/물리 기능을 추가한 것은 아니다. 아래 복합 변형 재시험은 현재 제공하는 **4점 엔진 API**를 사용했다. 사용자에게 도안의 예비 접기를 요구하는 방식으로 되돌리지 않는다.

## 재실행 결과

원본의 초기 단계 그림에서 계산한 좌표를 동일한 종이접기 엔진에 직접 전달했다. 최종 메시나 면 데이터를 강제로 교체하지 않았다. **엔진 자동 진단이며 마우스로 완주한 시험이 아니다.** 작품 5종 모두 완성 판정은 아직 하지 않았다.

| 모델 / 원본 도안 | 생략한 단계 | 실제로 실행한 결과 | 다음 검증 대상 |
|---|---|---|---|
| [물폭탄](https://origami.me/waterbomb/) | 웹 1~2단계의 예비 접기 | 새 종이에서 바로 베이스 변형 후보 생성. 2조합 생성, 표본 포즈 성공 합계 12개 | 웹 3단계의 삼각 베이스와 실제 형상 일치 여부 |
| [점프 개구리](https://www.japansociety.org.uk/usercontent/3bc1ed5a28641e243974254376c82e51/Jumping-Frog-Origami-Instructions.pdf) | PDF 1, 3~4단계 | 2단계 반 접기 1회 후 곧바로 5단계 후보 시험. 4조합 생성, 표본 포즈 성공 15개 | 두 겹을 유지한 베이스 형상. 이전 3단계 펼치기 실패는 이 경로에서 요구되지 않음 |
| [종이학](https://californiamuseum.org/wp-content/uploads/CAM_Uprooted_CraneInsturctions.pdf) | 초기 두 접기는 실제 형태 변화이므로 유지 | 1~2단계 접기 성공. 주머니 변형에 시험한 8조합은 후보 생성 0개 | PDF 3~4단계의 주머니 벌리기·눌러 펴기. 다른 조작 경로까지 불가능하다는 뜻은 아님 |
| [백합](https://www.origami-fun.com/support-files/origami-lily-print.pdf) | PDF 1~2단계 | 새 종이에서 바로 베이스 후보 시험. 2조합 생성, 표본 포즈 성공 12개 | PDF 3단계 베이스 형상. 이후 꽃잎 접기는 미검증 |
| [드래곤 v2](https://origami.me/dragon-advanced/) | 웹 1, 4단계 | 웹 3단계 반 접기와 5단계 앞쪽 한 겹 접기 성공, 총 2회 | 웹 6단계 이후는 아직 미실행. 현재 정지는 실행 범위의 끝이며 새로운 실패 판정이 아님 |

‘표본 포즈 성공 수’는 앵커·선택 범위별 ±45/90/135/180° 중 허용 범위 안에서 계산에 성공한 횟수의 합계다. 서로 다른 최종 형상의 개수나 도안 단계 통과 수가 아니다. 4점 후보 미리보기는 저장 레시피의 확정 횟수에 포함하지 않았다.

검증 순서는 기초 베이스에서 복합 형상으로 진행하는 테스트 순서다. 사이트 간 공통 난이도 등급이 아니며 드래곤 v2의 원문 등급은 Low-Intermediate다.

## 수정된 보강 우선순위

1. **점 지정 → 바로 벌리기/접기:** 3점 조작의 각 점 역할과 드래그 방향을 입력 처리에 연결한다. 현재 4번째 점 대기 상태와 구분하고, 기존 2점/4점 접기를 깨뜨리지 않는다.
2. **선택한 면과 겹의 범위 유지:** 겹친 종이에서 사용자가 고른 면 또는 면 묶음만 움직이는지 확인한다. 겹 번호와 원래 종이의 연결 관계를 함께 추적한다.
3. **여러 면의 연동 변형:** 점을 지정하면 엔진이 필요한 접힘선과 패널 분할을 만들고, 주머니/베이스가 목표 모양으로 변하는지 검증한다. 플레이어에게 미리 접었다 펴도록 요구하지 않는다.
4. **완성 형상 검증:** 중간의 면 길이·접합부·자기충돌·고정 면 유지와 최종 모양을 함께 검사한다. 예비 접기의 성공 여부로 대체하지 않는다.
5. **실제 작업량 기준 제한 검토:** 현재 10회 제한은 남아 있으나, 예비 접기를 포함한 이전 횟수로 상향 필요성을 단정하지 않는다. 생략 가능한 단계를 제외한 실제 제작 경로에서 다시 평가한다.

접힘선 정보는 동작 계산·저장에 필요한 경우 엔진 내부에서 관리한다. 이를 플레이어가 반드시 수행해야 하는 ‘선 만들기 과정’으로 취급하지 않는다. 이전의 ‘예비 접기 기록 보강’을 게임 기능의 P0 요구로 두었던 판단도 수정한다.

## 변경 및 증거

- 13점 배열과 게임 런타임은 이번 수정에서 변경하지 않았다.
- Editor 진단 도구에서 표시용 예비 접기를 건너뛰도록 변경하고 5종을 재실행했다. 컴파일 및 배치 실행 종료 코드 0을 확인했다.
- [이번 결과 JSON](results-direct/results.json): 생략 단계, 요청 좌표, 확정 횟수, 레시피, 판정.
- [이번 실행 로그](unity-origami-audit-direct.log), [소스 해시](source-manifest.json).
- [이전 예비 접기 포함 기록](2026-11-10-precrease-baseline.md)은 역사 자료다. 현재 판단은 이 문서를 따른다.

Unity 메뉴 `Tools > FlyEditor > Validation > Origami feasibility audit`의 기본 출력은 이제 `Docs/OrigamiAudit/results-direct`다. 환경변수 `FLYEDITOR_ORIGAMI_AUDIT`로 변경할 수 있다. 같은 출력 경로로 재실행하면 그 경로의 결과가 갱신된다. 기존 `results` 기록은 유지했다.
