# 뒷겹의 선 기준 접기 선택 수정 — 2026-11-12

## 재현과 원인

사용자에게서 확보했던 4단계 종이에서 시작한 6단계 꽃잎 저장본을 바탕으로,
실제 Input System 클릭으로 앞쪽 두 면을 좁히고 뒤집은 후 뒷면에 두 점을 찍었다.
수정 전에는 영역만 노란색으로 표시되고 `NeedsHinges` 상태로 남았다.
사진 속 현재 저장본 자체를 확보한 것은 아니며, 같은 증상을 보이는 조작 순서를 별도로 재현했다.

`PaperSheet.LastFoldPartition`은 이전 평면 접기의 움직인/남은 물질을 구분한다.
하지만 남은 쪽에는 서로 다른 날개·몸통이 함께 들어갈 수 있다.
기존 `Plan`은 그 집합 전체를 시작점으로 넣었고, 선택하지 않은 부분의 연결이
겹 경계에 걸리면 현재 선택한 뒷면까지 접을 수 없다고 거부했다.
재현 로그의 실패는 선택 면 3이 아니라, 관계없는 면 18에서 24로 넘어가는 검사였다.

## 공통 엔진 변경

`PaperSheet.Plan`의 기존 계획이 성공하면 그대로 사용한다.
계획이 실패했고 이전 접기의 겹 구분 정보가 있을 때만, 현재 클릭한 면을
시작점으로 물질 연결 관계를 다시 탐색한다.

- 이전 접기로 나뉜 겹 경계를 그대로 지킨다.
- 연결된 종이 조각은 함께 움직인다.
- 고정 부분으로 연결되는 비공선 접합을 끊거나 반대 겹으로 넘어가는 동작은 계속 거부한다.
- 충돌 제한, 종이 두께, 면적, 저장 형식은 변경하지 않았다.
- 학 단계 번호, 도안 종류, 특정 면 번호·좌표를 런타임 분기에 사용하지 않았다.
- 사용자의 조작은 두 점 선택 → 원하는 쪽 클릭 → 각도 조절로 같다.

## 검증

`RearLeafSelectionVerification.Run`:

- 두 점으로 앞면을 좁힌 상태 / 네 점으로 좁힌 상태
- 접는 축 -3°, 0°, +3° 변화와 양 끝점 순서 반전: 12개 사례
- 0~180°의 3° 간격: 732개 자세
- 앞쪽 물질 꼭짓점 고정 확인 26,352회
- 초록색 메시와 실제 이동 영역 일치
- 반대 방향 충돌 차단, 모든 물질 접합과 면적 보존
- 180° 완료, 직렬화 재생, 되돌리기·재실행
- 6개 사례는 기존 전체 집합 탐색 실패를 재현하고 새 연결 성분 탐색으로 성공

같은 실행에서 비행기 날개 64개 시퀀스/3,968개 자세, 180° 날개 이후 반대 날개 16개 시퀀스,
제트형 가장자리 8개 사례/368개 자세를 통과했다. 기존 반대 날개 누출 재현은 여전히 거부된다.

실제 Input System 클릭 경로에서도 수정 전 8단계 실패 상태가 수정 후 9단계 -180°로 완료됐고,
반대쪽 좁히기를 이어 10단계 -180°까지 완료했다. `input.jsonl`은 해당 조작 기록이다.

`before.png` / `selected.png` / `fold-09.png` / `fold-10.png`는 Unity 작업대 RenderTexture 원본 캡처다.
모든 임의의 접기가 가능하다는 검증은 아니며, 물리적으로 막히는 선은 기존처럼 거부한다.

## 재실행

프로젝트 경로를 사용하는 Unity batch 실행에 다음 환경 변수를 설정한다.
`FLYEDITOR_REAR_ROOT` = 이 문서가 있는 폴더의 절대 경로.
`-executeMethod FlyEditor.Editor.RearLeafSelectionVerification.Run`

입력: `repro-eight.json`, `front-eight.json`, `repro-line.json`.
결과: `regression.log`.

추가 회귀 결과 (`continuation.log`): 실제 입력으로 만든 10단계 저장본과 기존 16단계 학 두 종류,
총 42단계의 면적·접합·저장 재생 통과. 회전/좌우 순서가 다른 꽃잎 8개 사례와
보이는 면 선택을 거친 앞뒤 꽃잎 4개 연속 접기/148개 자세/가려진 면 선택 8개 검사도 통과했다.
