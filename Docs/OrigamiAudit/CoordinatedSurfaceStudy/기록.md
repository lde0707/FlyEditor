# 연결된 지지면·보조 접힘 공통 엔진 검증

검증일: 2026-11-12. Unity 6000.5.3f1. 검증 범위는 접힌 주머니의 연결 지지면, 보조 관절 생성, 교차점 입력 해석, 연속 각도 조정과 저장 재생이다. 드래곤과 꽃은 시험 입력이며, 완성 도안으로 판정하지 않는다.

## 결과와 적용 범위

- 이전 드래곤 실패 상태인 **7회 접기 체크포인트**를 그대로 불러왔다. 예전 `intersection-petal.json`의 이동점·기준점·양옆 두 점과 최종 실제 입력 레시피의 좌표 차이는 **네 점 모두 0**이다.
- 실제 화면 클릭·드래그로 0 → 78 → 180도까지 접고 마우스를 놓았다. 접기 기록이 7 → 8로 증가했다. 예비 접기나 별도 확정 버튼, 도안 전용 메쉬 교체는 사용하지 않았다.
- 입구 양끝을 3·4번으로 고르는 방식도 작동한다. 기존처럼 접힘 교차점을 고르면, 같은 재료 면의 경계와 길이 조건이 일치하는 경우에만 실제 입구를 추론한다. 아무 내부점이나 다른 겹의 점을 바꾸어 잡지는 않는다.
- 기본 주머니 앞·뒷면 16개 동작/128개 자세, 길이 비율 18개 수학 검사, 환경 변형 64개/832개 자세를 통과했다. 원래의 겹 분할·양쪽 날개·꽃잎·제트·저장 회귀도 통과했다.
- 이것은 주머니 계열의 연결 관절과 보조 접힘에 대한 개선이다. 모든 곡면·닫힌 함몰·임의 비평면 상태를 해결하는 탄성 종이 엔진 전체가 완성됐다는 뜻은 아니다.

## 공통 엔진을 바꾼 내용

### 실제 지지 관절을 추적

기존 계산은 선택한 영역과 지지면 전체가 정해진 두 삼각형 안에 들어와야 했다. 또한 지지 관절을 `Lerp`로 구해, 자유 가장자리보다 뒤쪽에 있는 관절이 가장자리 위치로 제한됐다. 새 경로는 원본 재료의 공유 변을 따라 지지면을 찾고 실제 관절 위치를 보존한다. 선택한 면과 지지면은 계산된 보조 접힘으로 분할한다. 떨어져 포개진 면은 접촉 관계일 뿐, 재료 연결로 간주하지 않는다.

### 관절 위치를 길이 조건으로 결정

`PaperHingeClosure`는 두 지지 관절의 위치를 길이 보존 조건으로 구한다. 준비 계산은 배정밀도·중앙 차분·감쇠 반복을 사용하며, 드래그 자세는 강체 관절 계산을 사용한다. 정해진 종이 크기, 드래곤 비율, 도안 단계, 면 인덱스를 런타임에 넣지 않았다. 독립적으로 유도한 대칭 4절 링크 공식과 18개 비율을 비교했다. 계산의 근사 결과도 각 자세의 강체 길이·재료 연결·면적 검사에서 다시 확인한다.

### 입력한 교차점으로 의도를 해석

`PaperPocketIntent`는 같은 재료 좌표계를 가진 연결 면의 실제 외곽 경계를 구한다. 내부 공유 변은 제외하고, 선택한 자유 가장자리를 지나는 연속 경계만 사용한다. 두 힌트가 계산된 접힘 교차점에 가까울 때만 주머니 동작으로 해석한다. 분리된 경계 구간을 건너뛰어 연결하거나, 화면에서 겹친 다른 재료를 붙이지 않는다. 실제 사용자가 찍은 네 점은 레시피에 그대로 남는다.

### 세계 좌표와 계산 좌표를 분리

세계 좌표에서 회전·이동을 왕복하면 밀착 직전의 매우 작은 층 차이가 손실되어 층 순서가 순환하는 문제가 재현됐다. `PaperLocalMotion`은 선택한 종이의 로컬 기준계에서 제약·접촉을 계산하고, 결과만 원래 기준계로 옮긴다. 회전 0/37/180/273도, 이동 좌표 (2,-1,3) 및 (1000,-2000,3000)을 검사했다. 접촉 검사를 끄거나 두께를 무시해 통과시키지 않았다.

### 미리보기와 입력 경로

큰 각도 입력도 2도 이하의 구간으로 나누어 기존 접촉·재료 연결 검사를 거친다. 실패하면 마지막 요청 전의 유효 미리보기와 조작점을 복원한다. 이는 샘플 경로 검사이며, 모든 연속 시간 충돌을 수학적으로 보장하는 완전한 CCD 인증은 아니다.

초록색은 직접 접는 조각, 파란 사선은 실제 관절 때문에 함께 움직이는 지지 조각, 원래 종이색은 고정 조각이다. 표시에도 실제로 계산된 조각과 보조 접힘선을 사용한다. 기존 IMGUI 흐름과 키 조작을 유지했다.

## 수치와 통과 판정

- 이전 요청과 실제 입력의 `pullTip`, `pullStop`, `pullLeft`, `pullRight` 차이: 모두 0.
- 실제 관찰기: `solver=coordinated`, `hingeHints=true`.
- 직접 이동 영역 샘플 16개, 보조 지지 영역 샘플 8개, 고정 영역 샘플 80개를 별도로 기록했다.
- 78도, 180도 미리보기 및 적용 후 고정 재료 중립면의 최대 이동량: 0.000000 모델 좌표 단위. 재료 위치 허용 오차는 0.002.
- 밀착 시 표시용 층 순서를 재정렬하면서 고정 영역의 두께 표시 오프셋은 최대 0.018(종이 두께 두 겹) 바뀌었다. 이를 재료 중립면 이동과 구분해 측정 파일에 남겼다. 물리 두께 위치와 층 순서를 완전히 분리하는 개선은 남아 있다.
- 실제 저장본 8회 접기 전체의 JSON 재생, 면적·연결, 되돌리기·재실행을 통과했다.

엔진 자세 검사, 실제 입력 검사, 완성 도안 판정은 별개다. 이번 성공은 작은 주머니 동작과 공통 제약 계산의 검증이며 드래곤 전체 완성 인증이 아니다. 원저자 도안: [Jo Nakashima Dragon](https://jonakashima.com.br/wp-content/uploads/2015/07/Dragon-Jo-Nakashima.pdf). 원본 PDF는 재배포하지 않았다.

## 일반화 검사

- 길이 비율 18개: 독립 4절 링크 공식과 관절 폐쇄 해 비교. 이것은 수학 계층 검사이며 18개 완성 작품을 뜻하지 않는다.
- 기본 사각 주머니 앞·뒷면 16개 동작/128개 자세: 종이 방향 4종과 양옆 점 순서 변경, 재료 연결·면적·저장 재생.
- 환경 변형 64개/832개 자세: 회전 4종 × 양옆 점 순서 2종 × 원본/분할 면 2종 × 층 간격·이동 좌표 2종 × 입구점/교차점 입력 2종. 층 간격과 이동 좌표는 이 시험에서 짝지은 조건이며 모든 독립 조합을 열거한 것은 아니다.
- 각 조건에서 각도 0,3,30,60,90,120,150,179.9,180,45,0,90,180도, 막히는 반대 방향, 유효하지 않은 각도, 미리보기 원본 보존, 부분 적용·되돌리기를 검사했다.
- 임의의 내부점과 다른 겹의 겹친 재료점을 관절 힌트로 바꾸어 잡지 않는 음성 사례를 통과했다.
- 기존 겹 분할 20개 선택선, 새 정책 날개 64개/512자세, 기존 날개 64개/3968자세, 180도 날개 16개, 제트 8개/368자세 등 기존 기준 검사를 유지했다. 각 검사 로그 자체의 범위를 따른다.

## 파일과 재현

- `fixtures/checkpoint-seven.json`: 수정 전 원본 실패 상태.
- `fixtures/intersection-petal.json`: 수정 전 원본 네 점 요청. 과거 실험의 미사용 JSON 필드는 보존했으며, 현 엔진이 도안 전용 옵션으로 사용하는 것은 아니다.
- `fixtures/player-hint-eight.json`: 이번 실제 교차점 입력으로 적용한 결과.
- `player/`: 최종 입력 전체, 단계별 실제 작업대·UI 사진, 선택점 위치, 레시피, 재료 측정.
- `boundary-player/`: 입구 양끝을 사용한 초기 실제 입력 대조군. 이 세션은 최종 교차점 해석·선 표시 개선 전 촬영이며 최종 입력 사진과 구분한다.
- `player-measurements.json`: 재료 중립면과 두께 표시를 구분한 실제 측정.
- `logs/`: 수정 전 실패, 진단과 최종 회귀 로그. 실패한 후보를 성공 결과로 집계하지 않았다.
- `verification/`: 사용한 검증 코드와 입력 전송·관찰기. 런타임 코드와 분리했다.
- `source-manifest.json`: 반영한 코드와 해시.

모듈 실행은 저장소의 `Tools/OrigamiQA/scripts/run_suite.py`와 `coordinated-surface` 또는 `coordinated-player-replay` suite를 사용한다. 실제 사용자 Unity가 아닌 닫힌 격리 프로젝트를 지정하고, `FLYEDITOR_COMPLEX_ROOT`를 이 문서 옆 `fixtures`로, 재생 검사에는 `FLYEDITOR_COMPLEX_PLAYER_RECIPE`를 해당 폴더의 `player-hint-eight.json`으로 지정한다. 사용자의 진행 저장본을 바꾸지 않는다.

## 남은 범위

현재 지원 조건은 네 점으로 정의되는 주머니와 그 재료 관절이 검증 가능한 상태다. 임의의 내부 네 점이 모두 의미 있는 주머니 동작이 되는 것은 아니다. 아직 해석되지 않는 다중 함몰·비평면 시작 상태, 연속 곡면의 탄성 변형은 별도 검증·개선 대상이다. 준비·드래그의 목표 PC 지연 시간은 이번 정확성 검사로 인증하지 않았다. 전체 드래곤의 다음 단계와 다른 고난도 모델 완성도는 계속 별도로 검증해야 한다.

## 등록한 QA 모듈 최종 실행

실제 저장소 카탈로그로 `coordinated-player-replay`를 실행해 exit 0 / PASS를 확인했다. `runner-verification-final/result.json`과 로그에 코드 해시·Unity 버전이 있다. 첫 실행은 카탈로그가 전역 테스트 클래스에 잘못된 namespace를 붙여 시작하지 못했다(`runner-verification/`). 진입점을 `CoordinatedPlayerReplayVerification.Run`으로 고쳤으며 런타임 코드는 바뀌지 않았다. 종료된 격리 편집기의 빈 잠금을 확인·제거한 재시도에서 통과했다. 이 실패는 모델 접기 실패와 구분한다.
