# 연속 접기에서 확인한 원인과 해결

## 완전히 펼친 뒤에도 옛 겹 경계가 새 접기를 막음

**재현:** 종이를 반 접고 기존 관절로 완전히 펼친다. 기존 선에서 벗어난 평행선을 고른 뒤, 그 선 너머로 옛 접힘 경계를 가로지르는 쪽을 접는다. 수정 전에는 유효한 접기 계획이 생성되지 않았다.

**원인:** `PaperSheet.LastFoldPartition`이 과거에 포개졌다는 기록으로 겹 소유권을 복원하면서, 그 재료 연결이 현재 완전히 펼쳐졌는지는 확인하지 않았다. 실제로는 다시 이어진 한 면인데 과거의 두 날개 경계가 계속 선택을 제한했다.

**해결:** 공유하는 원본 종이의 변과 재료 좌표계에서 현재 접선·접합 위치를 비교한다. 경계를 가로지르는 실제 연결이 모두 완전히 펼쳐진 경우에만 그 과거 경계를 이번 선택에서 제외한다. 접기 이력이나 종이 연결은 지우지 않는다. 일부만 열린 연결과 아직 접힌 겹은 기존 소유권을 유지한다. 이전 저장본의 선택 정책은 유지한다.

**재발 방지:** `SequenceConsistencyVerification`에 최소 재현과 정사각형·A4·Letter, 네 방향, 양쪽 접기 방향, 두 번에 나눈 펼치기, 평행/직교 새 선택선, 되돌리기·저장 재생 검사를 넣었다. 양쪽 날개를 번갈아 접고 펼치는 검사에서는 반대 날개의 고정 재료, 공유 변, 면적, 충돌 차단, 실패 요청의 원본 보존을 함께 확인한다. 수정 전 실패 로그는 `evidence/sequence-history-red.log`, 재현 시작 상태는 `fixtures/unfolded-book.json`이다.

## 연결된 면인데 클릭한 내부 조각에 선이 없다는 이유로 선택을 거절함

**재현:** 위의 펼친 종이에서 두 점을 연결한다. 선이 지나가는 조각 옆에 이어진 다른 조각을 클릭한다. 실제 입력에서는 “선이 이 면을 가로지르지 않습니다”가 표시됐다. 엔진 수정 후에도 화면 선택에서 별도로 발생했다.

**원인:** `FoldingDesk.ChooseSide`가 클릭한 볼록 다각형 하나와 선이 교차해야만 엔진에 접기 계획을 요청했다. 이전 접기의 내부 분할 조각을 플레이어가 접는 면 전체와 혼동한 판정이었다. 엔진이 검증할 수 있는 연결된 이동 영역이 화면에서 먼저 거절됐다.

**해결:** 같은 평면의 선택은 공통 재료 연결 엔진에 먼저 계획을 요청한다. 유효한 계획이 있으면 그 이동 조각을 선택·강조·드래그에 사용한다. 계획이 없으면 기존의 선 위치·다중 관절 필요·접촉 차단 안내를 유지한다. 겹 연결, 이동 범위, 충돌 검사를 우회하지 않는다.

**재발 방지:** `SequenceSelectionVerification`에서 앞/뒤 시점, 두 점의 순서, 선의 좌/우 위치를 바꾼 8개 선택과 초록색 강조 면적·실제 이동 영역 일치를 검사한다. 수정 전 컴포넌트 실패 로그는 `evidence/sequence-selection-red.log`이다. 같은 실제 마우스 좌표를 전후 비교한 입력은 `input-before/`와 `input-after/`에 남겼다. 수정 후 78도 미리보기 취소 → 다시 접기 → 되돌리기 → 반대 방향 -78도 접기와 저장 재생은 `SequencePlayerReplayVerification`으로 고정했다.

두 원인은 작품명·도안 단계·특정 면 번호에 분기하지 않는 공통 경로에서 수정했다. 전체 종이접기 기술이나 모든 연속 충돌을 인증한 결과는 아니다. 판정 근거와 재실행 명령은 `result.json`, `evidence/sequence-final-regression.log`, 저장소의 `Tools/OrigamiQA`에 보관한다.
