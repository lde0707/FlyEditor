# 사선 날개의 겹 선택 수정 — 2026-11-11

## 문제와 재현 범위

첨부 사진의 순서에 맞춰 모서리 두 번, 기수 좁히기 두 번, 몸통 반 접기를 구성했다. 기존 평행 날개 테스트와 달리 새 날개 접는 선은 꼬리 쪽 점에서 기수 꼭짓점으로 모인다.

겹쳐진 면의 원본 종이 좌표와 면 데이터는 유지되어 있었다. 기존 `LastFoldPartition`은 이전 접기선과 새 접기선이 5도 이내로 평행해야만 겹 이력을 적용했다. 그 결과 이번 사선 3종에서는 개별 날개 계획이 모두 거부됐다(`oblique-before.txt`). 이번 기준 코드에서 사용자가 보고한 동반 이동 자체까지 동일하게 재현한 것은 아니다. 이전 회귀 검사에는 구형 연결 탐색의 반대쪽 날개 동반 이동 사례가 별도로 포함되어 있다.

## 변경

- 새 선의 방향으로 겹을 추정하지 않고, 실제 완료된 180도 접기 당시 서로 포개진 면의 원본 종이 소속을 추적한다.
- 완료 직후의 이력을 사용하므로 한 날개를 먼저 열어도 반대 날개의 소속이 유지된다. 선택한 면과 겹치지 않았던 나중의 다른 접기는 제외한다.
- 한 날개 내부의 접힌 조각은 함께 움직일 수 있지만 반대 날개를 이동 대상에 포함하지 않는다. 연결을 찢어야 하는 선과 반대 겹을 뚫는 방향은 계속 차단한다.
- 0도 미리보기에서는 기존 겹 순서를 유지한다. 시작점에서 불필요한 접촉 순서 재계산 때문에 사선/회전 조합이 거부되던 문제도 수정했다.
- 조작과 전체 선택 모드는 유지한다. 두 점 선택 → 면 개별 선택 → 보이는 면 선택 → 드래그. 전체 선택은 의도대로 양쪽을 포함한다.

## 검증

- `FlyEditor.Editor.WingSideVerification.Run`: 기본/좁힌 기수, 4방향 회전, 양쪽 날개 먼저 선택, 평행선과 사선 3종. **64조합, 3,968개 미리보기 상태**. 반대쪽 원본 종이 정점 고정, 면적, 모든 재질 경계 연결, 충돌, 저장 재생, 되돌리기 검증 통과.
- `FlyEditor.Editor.WingSideVerification.RunFlat`: 첫 날개 180도 완전 접기 후 반대 날개 열기 **16조합** 통과.
- `WingPlyInputPlay.RunTapered`: 실제 Input System 마우스/키보드 이벤트로 몸통 반 접기, 사선 선택, 전체/개별 전환, 윗날개 76도, 아랫날개 -82도, 반대 날개 고정, 저장 재생, 되돌리기, 수정 취소 통과. 기수 준비 단계는 엔진으로 구성했고 아래쪽 시점은 테스트에서 지정했다. 컴퓨터 유즈를 사용하지 않았다.
- 기존 JetEdge 8조합/368상태 통과. 기존 충돌 확보, 꽃잎/주머니, 4점 접기, 역접기, 중첩 접기, 기체 성능/그립 회귀 검사 통과.
- 회귀 첫 실행은 도안 자료 환경변수 누락으로 중단됐으며, 올바른 자료 경로로 남은 전체 회귀를 재실행해 종료 코드 0을 확인했다.

`input/top-opening.png`는 윗날개가 움직이고 아래 면이 노출된 실제 테스트 화면이다. `input/both-wings.png`는 양쪽을 각각 연 상태다. 사용자 저장 종이를 직접 로드한 테스트는 아니며, 사진 순서를 재구성한 테스트다.
