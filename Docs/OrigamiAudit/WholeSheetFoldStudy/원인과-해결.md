# 종이 전체의 겹을 함께 반 접기

사용자 요구: 중앙선을 기준으로 겹친 아랫면까지 종이 전체를 함께 반으로 접는다. 이번 작업은 해당 문제에 한정하며, 드래그 박스 선택이나 대량 오류 탐색을 추가하지 않았다.

## 원인

엔진에는 전체 겹 선택 범위(`Stack`)가 있었지만 입력 경로가 닫혀 있었다. 화면은 보이는 면 범위만 표시했고, 숫자 2키도 다시 `Top`을 선택했다. 따라서 플레이어는 전체 겹 접기를 요청할 방법이 없었다. 재현용 좁은 비행기에서 중앙선을 긋고 2키와 면 드래그를 입력해도 `scope=Top`, 각도 0에 머물렀다.

## 해결

- 두 점으로 접는 선을 만든 뒤 **전체 겹 [2]** 버튼 또는 숫자 **2**로 모든 겹을 명시적으로 선택한다.
- 선 한쪽의 면을 드래그하면 그쪽의 모든 겹이 함께 접힌다. 접는 중 **C**로 180도까지 밀착할 수 있다.
- **면 접기 [1]**과 숫자 **1**은 기존 보이는 면 범위를 사용한다.
- 한 번 접기를 끝내면 기존 `Browse` 전이를 통해 보이는 면 선택으로 돌아간다. 다음 날개 접기까지 전체 겹 범위가 남지 않는다.
- 네 점 복합 접기나 드래그 중에는 새 범위 전환 버튼을 비활성화한다. 기존 충돌과 연결 검사를 우회하지 않는다.

## 검증과 한계

- `WholeSheetFoldVerification`: 기본/좁은 비행기 × 네 방향의 8개 조건, 48개 각도에서 전체 겹 면적·연결·저장 재생·되돌리기와 범위 복귀를 검사했다.
- `evidence/session-a`: 수정 전 실제 마우스·키보드 입력. 2키 후에도 Top이며 반 접기를 수행하지 못했다.
- `evidence/session-b`: 같은 입력으로 Stack 전환 후 180도 접기 완료. 독립 계산으로 이동/고정 재료를 확인하고 6개 상태의 저장 이력과 격리 파일 저장을 검증했다.
- 기존 개별 날개 분리와 반대쪽 고정 검사를 다시 통과했다. 전체 겹을 기본 선택으로 바꾸지 않았다.
- 초기 EditMode의 합성 키 입력은 눌림 이벤트가 전달되지 않아 실제 키 입력 증거로 사용하지 않았다. 키 경로의 수정 전후 증거는 위 Play 모드 세션이다.
- 사용자가 사진과 같은 종이를 적용했다고 알려 주었으나, 읽을 수 있는 저장 파일에는 해당 이력이 없었다. **사진과 동일한 이력에서의 검증은 미확보**이며, 비슷한 좁은 비행기 형태로 재현한 결과다.
- 사용자 게임 저장 데이터를 변경하지 않았다. 이 폴더의 저장본은 격리 재현용이다.

드래그 박스 선택은 이번 변경에 포함하지 않았다. 도입한다면 면 선택 모드에서만 사용하고, 보이는 겹/전체 겹 범위와 실제 이동 미리보기를 따르는 별도 입력 기능으로 다룬다.
