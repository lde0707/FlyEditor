# 실제 연속 조작에서 확인한 원인과 해결

## 새 엔진 결함의 재현 여부

이번 세 흐름에서는 새로 막히는 공통 엔진 결함이 재현되지 않았다. 기존 엔진 코드의 해시를 유지하고, 실제 입력과 재료·메쉬 측정에 대한 회귀 검사를 추가했다. 도안명·단계·특정 면 번호를 사용하는 런타임 처리는 추가하지 않았다.

앞서 수정한 ‘완전히 펼친 뒤 과거 겹 경계가 남는 문제’와 ‘내부 조각 하나에 선이 없다는 이유로 연결된 면을 선택하지 못하는 문제’는 새 종이에서 접기→기존 관절로 펼치기→새 평행선/대각선 재접기로 재검증했다. 두 문제가 이번 실제 입력에서는 재발하지 않았다. 원래 원인과 수정 내용은 [이전 원인 기록](../SequenceConsistencyStudy/원인과-해결.md)에 있다.

## 테스트 중 겹이 함께 움직이는 경우의 판정

**원인:** 기존 접힘축과 직교하는 새 선을 선택하면, 선택 부분이 기존 관절을 통해 반대 겹에 연결된 경우가 있다. 그 연결을 유지하는 단일축 동작에서는 두 조각이 함께 움직여야 한다. 이 경우를 ‘겹 선택 누출’로 판정해 연결을 끊으면 종이가 찢어진 것과 같은 결과가 된다.

**해결:** 단순한 화면 겹침과 원본 종이의 공유 변을 구분한다. 독립 겹 검증에서는 기존 관절과 평행한 접기를 사용해 한 겹만 움직일 수 있는 상황을 만든 뒤, 윗겹과 아랫겹의 원본 재료 범위를 각각 검사했다. 서로 연결돼 함께 움직여야 하는 동작은 별도로 취급했다. 충돌이나 재료 연결 검사를 끄지 않았다.

## 테스트 입력 혼입과 버튼 입력 방식

**원인/제한:** 첫 진단 세션은 실제 마우스·키보드와 자동 입력 장치를 같은 격리 게임에서 사용해 입력 혼입 가능성이 있었다. 또한 Input System 포인터 이벤트만으로는 IMGUI의 ‘새 종이’ 버튼 클릭을 검증할 수 없었다. 이 버튼의 자동 클릭 실패를 제품 엔진 오류로 확정하지 않았다.

**해결:** 격리 Unity 프로세스 안에서만 물리 입력 장치를 비활성화하고 전용 마우스·키보드 이벤트로 재실행했다. 사용자 컴퓨터의 다른 앱과 실제 개발 프로젝트 입력은 건드리지 않았다. 두 번째 새 종이 흐름은 빈 저장 경로를 사용하는 별도 Unity 프로세스로 시작했다. 실제 ‘새 종이’ 버튼 자체의 클릭 성공은 이번 PASS 범위에 포함하지 않는다. 첫 진단 세션과 `session-b`의 22~27번 시도도 세 흐름의 성공 집계에서 제외했다.

## 같은 실패를 다시 잡는 방법

`three-player-flows` QA 모듈은 실제 조작 저장본에서 윗겹/아랫겹의 재료 범위, 고정 재료 위치, 접촉 차단, 취소·되돌리기, 실제 저장 파일과 새 프로세스에서 읽은 기체의 일치를 검사한다. 화면에 그려진 초록색 메쉬의 면적도 실제 이동 면과 비교하며 종이 두께의 옆면은 별도로 제외한다. 원본 재료 좌표가 기준이므로 재생 후 면 번호나 런타임 식별자가 바뀌어도 같은 방식으로 검사한다.

재실행은 저장소 `Tools/OrigamiQA/scripts/run_suite.py`의 `--suite three-player-flows`를 사용하고, `FLYEDITOR_THREE_PLAYER_ROOT`는 이 문서 옆 `evidence`로 지정한다. 결과·코드 해시·선택과 고정 영역 측정은 `result.json`, `measurements.json`, `source-manifest.json`, `verification/`에 있다. 이 세 흐름의 통과가 모든 접기 기술이나 연속 시간 충돌 전체의 인증을 뜻하지는 않는다.
