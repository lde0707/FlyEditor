# 학 도안 재접기와 변 선택 — 2026-11-11

`index.html`에서 순서대로 이미지를 볼 수 있습니다. `steps/`에는 시작 화면과 16회 접기 직후의 원본 PNG 17장이 있고, `recipes/`에는 각 단계까지 재생 가능한 접기 데이터가 있습니다.

## 적용한 조작

1. 선택된 점이 없는 상태에서, 펼치려는 주머니의 입구 변에 마우스를 올립니다. 점과 점 사이 부분을 가리키세요.
2. 펼칠 수 있는 변만 민트색으로 강조됩니다.
3. 변을 클릭해 선택하거나, 바로 가운데 방향으로 드래그합니다.
4. 주머니가 벌어지고 양옆이 함께 눌러 펴집니다. 반대로 끌면 접기 진행이 되돌아갑니다.
5. 끝에 가까워지면 180도로 보정됩니다. 놓으면 적용합니다. Esc는 취소, Z는 한 단계 되돌리기입니다.

뒷면 주머니는 종이를 회전해 해당 겹이 보이게 한 뒤 변을 잡습니다. 기존 점 선택/4점 접기와 전체·개별 면 선택은 유지됩니다. 평평한 새 종이나 처리할 수 없는 변을 주머니로 강제 변형하지 않습니다.

## 공통 엔진 변경

- 변이 속한 실제 종이 면과 원본 종이 좌표의 연결 변에서 주머니의 중심축을 찾습니다. 화면에서 포개진 것만으로 다른 겹을 연결하지 않습니다.
- 기존 공통 양옆 점 추론과 정밀 주머니 해법을 연결했습니다. 사용자가 네 점을 직접 입력할 필요가 줄었습니다.
- 미리보기와 적용은 같은 `PaperCornerPull` 해법을 사용합니다. 충돌 검사, 종이 면적과 연결 경계, 저장·재생·되돌리기를 유지합니다.
- 새 변 접기부터 방향이 다른 겹 묶음도 각각 두께 순서를 정리합니다. 새 저장 필드 `localLayerPacking`으로 구분하고 이전 레시피는 기존 처리를 유지합니다. 이는 정확한 탄성/종이 두께 물리 전체를 완성했다는 뜻이 아닙니다.
- UI는 기존 상태 흐름에 `EdgePress`를 추가했습니다. 변 위에서 계산한 후보는 같은 변에 머무르는 동안 재사용하며, 점 선택이 변 선택보다 우선합니다.

## 도안 진행과 남은 부분

대각선 반 접기 → 삼각형 반 접기 → 앞뒤 주머니 → 앞뒤 꽃잎 → 목·꼬리 폭 좁히기 → 몸통 접기 → 목·꼬리 들어 올리기 → 부리 → 양쪽 날개 순서로 16회 접기를 진행했습니다. 자국만 만드는 예비 접기는 이전 요청대로 생략했습니다. 뒤집기와 좌우 반복을 풀어 기록했으므로 파일 번호는 첨부 도안의 번호와 다릅니다.

**도안 13의 몸통에 바람을 넣듯 부풀리는 동작은 아직 구현되지 않았습니다.** 마지막 결과는 날개가 펼쳐진 납작한 몸통의 학입니다. 중앙에 연결된 8개 면, 40개 변을 검사했지만 현재 공통 주머니 해법에서 유효한 몸통 벌리기 후보가 나오지 않았습니다. 양쪽 날개 뿌리와 몸통을 함께 움직이는 추가 해법이 필요합니다. 충돌을 무시하거나 완성 메시로 교체하지 않았으며 도안 전체가 완성됐다고 판정하지 않았습니다.

## 검증과 촬영

- 새 주머니 변 선택: 회전 4방향 × 앞/뒤 먼저 접기, 8조합 / 592개 자세. 정확한 사각 기본형, 역방향 충돌, 앞뒤 스크럽, 부분/완전 접기 저장·재생·되돌리기 통과.
- 실제 Input System 테스트: 변 강조 → 클릭/드래그 → 진행/되돌림 → 180도 보정 → 놓기, 다른 겹 고정, 저장·재생, Z, 클릭 선택 후 Esc 통과.
- 학 전체 16회: 매 단계 면적, 모든 원본 종이 연결 경계, 저장 재생 검사 통과. 새 주머니 처리로 내부 면 번호가 바뀌므로 이후 선택을 원본 종이 좌표로 다시 찾습니다. 학 좌표와 순서는 Editor 검증 코드에만 있으며 런타임에는 도안 전용 분기가 없습니다.
- 기존 사선/평행 날개 64조합 / 3,968개 자세, 180도 날개 16조합, 가장자리 맞추기 8조합 / 368개 자세 및 주머니·꽃잎·되접기·4점·기체 성능 회귀 검사 통과.
- 원본 PNG는 Unity 카메라가 실제 접힌 메시를 렌더링한 이미지입니다. 초기 캡처의 MSAA 미리보기 오류를 수정하고 17장 모두 다시 촬영했으며 크기와 비어 있지 않은 것을 검사했습니다.
- 16회 전체 진행은 엔진 API를 사용한 재접기입니다. 모든 단계를 마우스로 처음부터 끝까지 접은 검증은 아니며, 새 변 드래그 조작은 별도 실제 입력 검사로 확인했습니다. Computer Use는 사용하지 않았습니다.
