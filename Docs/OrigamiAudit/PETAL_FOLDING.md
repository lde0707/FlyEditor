# 예비 접기 없는 꽃잎 접기와 후속 동작 검증

2026-11-10 · Unity 6000.5.3f1 · 한 변 13점 유지

## 결과와 범위

**종이학 앞·뒷면의 꽃잎 접기와 그다음 네 번의 가장자리 좁히기를 공통 엔진으로 실행했다. 종이학 완성은 아직 실패했다.** 총 10번의 형상 접기를 확정했고 예비 접기는 0회다. 목·꼬리의 여러 겹을 벌려 뒤집는 다음 단계에서 진행이 막혀 부리와 날개를 완성하지 못했다.

꽃잎 접기는 사각 기본형의 네 점으로 필요한 두 각 이등분선과 가로 접힘선을 계산한다. 격자에 없는 교차점을 사용자가 찍거나, 접었다 펴서 선을 남길 필요가 없다. 새 교차점은 실제 메시 꼭짓점으로 생성되므로 이후 접기에서 선택할 수 있다. 도안 이름, 단계 번호, 완성 메시, 종이학 전용 좌표는 런타임에 들어 있지 않다. 도안 좌표는 Editor의 재현 검사에만 있다.

참고 도안: [California Museum 종이학 안내](https://californiamuseum.org/wp-content/uploads/CAM_Uprooted_CraneInsturctions.pdf).

## 플레이어 조작

- 꽃잎 접기: **들어 올릴 끝점 → 반대편 고정 꼭짓점 → 왼쪽 모서리 → 오른쪽 모서리**. 평평하게 겹친 연 모양과 연결된 안쪽 면을 찾으면 꽃잎 접기로 전환한다. 면 또는 끝점을 끌어 움직이고 놓으면 적용된다.
- 가장자리 맞추기: **옮길 변의 두 끝점 → 기준선 위의 두 점**. 처음 점이 기준선의 연장선 위에 있는 경우 각 이등분선으로 접는다. 예를 들어 새 기본형에서는 아래 끝점·옆 모서리·가운데 합쳐진 모서리·위쪽 날개 끝점을 사용한다. 가려진 내부 점을 클릭할 필요가 없다.
- 네 번째 점은 보이는 다른 면에서도 선택할 수 있다. `Tab`으로 겹을 명시적으로 골랐다면 그 겹 선택을 유지한다.
- `E` 마지막 각도 수정, `Esc` 수정 취소, `C` 밀착, `Z` 되돌리기, 빈 공간 클릭 선택 해제를 유지한다. 별도 접기 확정 버튼이나 도안 모드는 추가하지 않았다.

## 공통 계산과 상태 전이

선택 흐름은 기존 `FirstPoint → SecondPoint → PickSide → RightFlank → PickSide → AdjustAngle → FirstPoint`를 사용한다. 네 점을 정했을 때 기하 조건에 따라 가장자리 맞추기, 꽃잎 접기, 기존 주머니/4점 변형을 선택한다. 계산 클래스에는 입력 FSM을 중복 구현하지 않는다.

꽃잎 접기에서 움직이는 끝점 T, 고정 꼭짓점 U, 양옆 꼭짓점 L/R을 사용한다. T의 각 이등분선이 LU/RU와 만나는 점 P/Q를 계산한다. TP·TQ·PQ를 따라 필요한 면만 분할한다. T가 PQ 주위를 회전하는 동안 L/R은 고정된 삼각형 변 길이와 움직이는 삼각형 변 길이를 동시에 만족하는 원·구 교점으로 결정한다. 완전히 닫힐 때는 동일한 거리 조건을 검증한 평면 반사 좌표를 사용한다.

- 겹 선택은 화면상의 높이만으로 하지 않고 원래 종이의 좌표와 공유 경계로 추적한다. 선택한 바깥 면 및 그 면에 실제로 이어진 안쪽 면만 함께 움직인다.
- 면적, 삼각형 변 길이, 평면성, 유효 좌표와 다른 면 교차를 검사한다. 충돌한 방향을 강제로 통과시키지 않는다.
- 평평하게 닫힌 뒤 면 좌표계를 정리해 새 꼭짓점을 다음 접기에 사용한다. 같은 각도 요청은 마지막 유효 미리보기를 재사용한다.
- 새 레시피에는 `adaptiveCreases`와 `compactLayers`를 저장한다. 기존 레시피의 기본값은 false이므로 이전 계산 경로를 유지한다. 저장·되돌리기 후 새 단계의 면 번호가 달라지지 않는지 재생 검사한다.
- 새 레시피의 평평한 겹에서는 비어 있는 겹 번호를 제거해 순서를 유지하면서 불필요한 간격 증가를 막는다. 10회였던 접기 제한은 32회로 늘렸다. 512개 면 조각을 초과하는 확정은 거부하고 이전 상태를 보존한다. 이 수치는 모든 종이접기의 지원을 뜻하지 않는다.

10회 진행은 동일한 엔진 API로 연속 실행했다. 실제 InputSystem 입력 검사는 별도로 사각 기본형에서 꽃잎 접기, 중간 저장, 수정·취소·밀착, 다음 네 점 가장자리 맞추기까지 수행했다. 종이학 전체를 마우스로 완주했다는 뜻은 아니다. 그림은 실제 FoldMesh의 Unity 렌더다.

## 검증

- 4방향 × 양옆 점 순서 2종 = 8종: 앞뒤 꽃잎, 정확한 끝점 위치, 면적·연결부, 중간 각도 저장 재생, 역방향 조절, 되돌리기 통과.
- 기존 주머니 8종, 4점 변형 12종 및 한 겹 접기·접촉·벌리기·저장·기체 성능 회귀 검사 통과.
- 32번 접기 한도와 오래된 Turn 재사용 거부 검사 통과.
- 실제 입력: 꽃잎 선택 → 90도 → E → Esc → E → C → 다음 점 선택 → 빈 곳 클릭 → Z → 새 기본형의 가장자리 맞추기 통과.
- 실제 기존 입력: 겹 전환으로 네 번째 점 선택, 주머니 벌리기·밀착, E/Esc/C/Z 통과.
- 성능 수치나 모든 비정형 종이에 대한 물리 정확도를 보증하는 검사는 하지 않았다.

메뉴:
- `Tools > FlyEditor > Validation > Petal folding`
- `Tools > FlyEditor > Validation > Crane petal audit`

배치 진입점: `FlyEditor.Editor.PetalFoldingVerification.Regression`, `FlyEditor.Editor.CranePetalAudit.Run`.
검사 결과 경로는 `FLYEDITOR_PETAL_AUDIT`로 지정할 수 있다. 기본 위치는 이 문서 옆 `results-petal/`이다.

## 다음 공통 개선이 필요한 곳

기존 `PaperInsideReverse`는 두 개의 단일 면에서 같은 접힌 경계와 근접한 끝점·축을 찾는 방식이다. 좁히기가 끝나면 하나의 목/꼬리가 여러 조각과 여러 겹으로 분할되어 이 가정에 맞지 않는다. 현재 자세와 중앙으로 책장처럼 넘긴 자세, 보이는 기존 꼭짓점에 대응하는 축 후보를 시험했지만 목·꼬리 뒤집기 계획이 생성되지 않았다.

다음 단계는 임의의 면 두 개가 아니라 **공유 재료 경계로 이어진 다겹 묶음**을 선택 단위로 삼아야 한다. 몸통의 고정 경계, 내부에서 벌어질 겹, 함께 움직일 끝부분을 분리하고, 벌림 → 뒤집기 → 재접촉 과정의 연결부와 충돌을 함께 풀어야 한다. 겹 번호 정리만으로 이 동작이 해결되지는 않는다. 잘못된 평면 닫힘이나 종이 찢어짐을 허용해 종이학 완성으로 처리하지 않았다.
