# 선으로 나눈 선택 영역과 실제 접기 일치 · 2026-11-12

## 변경
- FoldMesh: 고정 조각에는 선택 색을 칠하지 않고 Turn.movingFaces만 강조한다. 이전 면 전체를 카메라 앞으로 덧그리던 처리를 제거했다.
- 두 점을 고른 뒤 아직 어느 쪽을 접을지 정하지 않은 상태에서는 면 전체를 초록색으로 표시하지 않는다. 이동 후보가 정해지면 그 조각만 강조한다.
- 선택 점의 배경 색과 선 표시도 실제 면 깊이를 따른다. 숨은 겹 전체를 전면으로 끌어내지 않는다.
- 네 점 가장자리 맞추기는 계산한 PaperCornerPull을 선택 상태에 보관한다. 선택 미리보기의 EdgeTurn과 실제 드래그의 접기 계획이 같은 객체다.
- 각도 조절 중에도 실제 이동 조각만 초록색으로 표시하고, 네 개의 입력 보조선 대신 계산된 접는 선을 그린다.
- 기존 PaperSheet 분할/물리 연결/겹 분리/충돌 계산은 유지했다. 선택 조각 하나에서만 순회하도록 바꾸는 실험은 기존 연결된 날개 펼치기를 막아 적용하지 않았다.

## 검사
- SelectionRegionVerification: 5가지 검사, 위·아래 겹 각각 0~180도 3도 간격 총 122자세.
- 초록색 표면 면적 = 실제 이동 조각의 양면 면적. 초록색 삼각형 중심이 이동 조각 밖에 있는지와 고정 절반을 잘못 덮는지 검사.
- 반 접혀 포개진 종이의 위 겹/아래 겹을 각각 선택하여, 반대 겹의 원래 재질 좌표가 고정되는지 확인. 종이 면적, 모든 재질 연결부, 반대 방향 충돌, 저장 재생, 되돌리기 통과.
- 이전 사용자 상태에서 파생한 두 꽃잎 완료 상태에서 네 점 선택 전후의 표시를 검사.
- 기존 WingSide 64개/3968자세, 완전히 접은 날개 16개 연속 접기, JetEdge 8개/368자세 통과.

## 실제 조작 확인
- Input System 마우스/키보드 이벤트로 두 점 선택 → 오른쪽 면 선택 → C, 되돌리기 → 네 점 선택 → 면 클릭 → C 수행.
- 두 경우 모두 접기 6 → 7, 180도 완료.
- selection-plan.txt의 8번 기록: edge=True, pull=True, same=True. 강조 미리보기와 드래그가 같은 계획을 사용함.
- 첨부 PNG는 Unity 렌더 캡처다. 합성 이미지가 아니다.
- 검증은 위 사례 및 회귀 검사 범위이며, 임의의 모든 복잡한 접기 상태를 보장하지 않는다.
