# 꽃잎 주변 겹 정리 — 공통 접기 보조

## 결과

기존 21회 상태에서 다른 꽃잎 하나를 추가로 끝까지 들어 올렸다. 기존 접힘축으로 주변 겹을 세 번 정리하고 꽃잎을 접는 네 동작을 **한 번의 드래그·한 번의 되돌리기**로 묶었다. 저장 레시피는 22개 작업이며, 원시 동작으로 펼치면 25개다.

완성된 백합은 아니다. 첫 꽃잎은 내려 둔 상태이고 두 번째 꽃잎은 들어 올린 상태다. 나머지 두 꽃잎, 밑부분 좁히기와 최종 입체 모양은 아직 완료하지 않았다. 기존에 막혔던 모든 방향이 해결됐다는 뜻도 아니다.

- `before-21.json`: 수정 전 원본을 그대로 보존.
- `expanded-25.json`: 실제 충돌 검사를 통과한 개별 동작 경로.
- `continued-22.json`: 같은 종류의 준비와 접기를 하나로 묶은 저장 예제.
- `input/`: Unity 실제 Play Mode 작업대의 입력 검사 캡처.

## 조작

두 점을 선택하고 **양옆 점 찾기**를 누른다. 바로 접을 수 없으면 주변 겹을 정리할 경로와 양옆 보조점을 함께 찾는다. 네 점을 직접 고른 경우에도 막힌 꽃잎의 준비 경로를 찾는다.

찾은 뒤에는 기존처럼 면을 드래그하고 놓는다. 반대로 움직이면 같은 경로를 되짚는다. 슬라이더와 단축 선택은 0~100% 진행률로 표시한다. C는 끝까지 접기, E는 마지막 작업 수정, Z는 준비 과정까지 한 번에 되돌리기다. 경로를 찾는 중에는 Esc로 취소할 수 있다. 별도 벌리기 모드나 준비 동작별 확인 버튼은 없다.

경로 찾기는 작업대와 분리된 종이 사본에서 백그라운드로 실행한다. 찾는 동안에는 종이가 바뀌지 않는다. 취소·닫기·다른 종이로 교체하면 결과를 폐기한다. 경로를 못 찾으면 충돌 제한을 그대로 유지하고 선택을 보존한다.

## 공통 계산 규칙

1. 선택된 두 점이 정의하는 주머니 축과 겹치는 **기존 재료 접합선**만 준비 회전 후보로 쓴다.
2. 실제 재료 연결 관계로 움직일 묶음을 구한다. 화면에서 겹친다는 이유로 면을 연결하지 않는다. 준비 회전으로 새 면을 잘라 만드는 후보는 제외한다.
3. 각 준비는 기존 `Turn.Constrain`의 출발 겹 순서·회전 경로·면 교차 검사를 통과해야 한다. 실제로 회전시킨 결과에서 다음 준비를 찾는다.
4. 준비가 끝난 뒤 기존 꽃잎 계산의 전 구간을 검사한다. 네 점이 지정됐으면 이를 유지하며, 두 점 보조 요청이면 실제 꼭짓점에서 양옆 점을 찾는다.
5. 최대 3회 준비, 최대 192개 상태로 탐색을 제한한다. 실패는 접기 불가능의 수학적 증명이 아니며, 자동 보조가 이번 범위에서 경로를 찾지 못했다는 뜻이다.
6. 계산은 선택 면의 강체 좌표계에서 수행한 뒤 화면 좌표계로 돌린다. 종이 전체의 위치·기울기에 따른 수치 오차가 얇은 겹의 순서를 바꾸지 않도록 했다. 충돌 허용치를 넓히지 않았다.

백합 이름, 도안 단계 번호, 고정 꼭짓점 좌표, 특정 면 번호는 런타임 알고리즘에 들어가지 않는다. 좌표가 있는 백합 사례는 Editor 검증 데이터에만 있다. 완성 메시 주입, 접촉 검사 생략, 종이 늘리기는 사용하지 않는다. 기존 중립면 기반 접촉 모델의 한계는 그대로이며, 유한 두께 종이의 모든 물리 현상을 증명하는 솔버는 아니다.

## 상태와 저장

작업대 상태는 `PickSide / RightFlank → PreparingClearance → PickSide → AdjustAngle / PullCorner`로 연결한다. 준비 중 Esc·닫기는 실행을 취소하고, 결과 적용 시 종이 참조가 바뀌었는지 다시 검사한다.

`FoldStep.clearance`에 실제 준비 회전의 축·면·방향·각도를 기록하고 `clearanceDirection`에 진행 방향을 기록한다. 재생할 때 경로를 다시 탐색하지 않는다. 저장된 준비 회전과 꽃잎 전개를 다시 검증한다. 예전 저장에는 이 배열이 없어 기존 계산을 유지한다. 부분 진행 상태도 저장·재생하고 E로 이어서 수정할 수 있다.

## 검증

- 실제 다음 꽃잎: 두 점에서 보조점 찾기 → 준비 3회 → 꽃잎 180도 완료.
- 합성 동작의 2도 간격 91개 자세, 앞뒤 되짚기, 부분 저장/재생, 전체 저장/재생, 한 번의 되돌리기.
- 전체 종이를 기울이고 이동한 4가지 배치와 양옆 점 교환: 8개 사례, 104개 자세의 면적·재료 접합부 보존.
- 반대 진행, 잘못된 각도·저장 앵커·준비 회전 방향, 취소된 탐색 거절.
- 22개 작업 전체 재생: 222개 주머니/꽃잎 자세, 15개 일반 회전 자세, 반대 방향 차단 3건 유지.
- 실제 Play Mode: 보조 콜백, 백그라운드 탐색 취소, 실제 InputSystem 포인터 드래그, 부분 적용, E·Esc·C·Z, 닫기 시 취소.
- 기존 보조점 선택, 닫힌 주머니, 네 점 정렬, 안쪽 접기, 중첩 접기, 학의 목/꼬리, 비행기 도안 등의 회귀 검사 통과.
- 업데이트된 예제를 실제 작업대 메뉴로 열고 닫아 기존 기체 저장과 연구 포인트가 보존되는 것 확인.

배치 모드에서는 IMGUI 버튼에 OS 클릭을 주입하지 않았다. 동일 버튼 콜백을 호출하고 이후 실제 포인터·키 입력을 검사했다. 캡처는 실제 Unity 작업대 카메라이며 전체 OS 화면 캡처는 아니다. FPS/GC 프로파일링 결과를 주장하지 않는다.

검사 메뉴: `Tools > FlyEditor > Validation > Petal clearance sequence` 및 `Lily study check (incomplete)`.

## 남아 있는 범위

기존에 먼저 시도한 다른 꽃잎의 방향에서는 제한된 탐색으로 경로를 찾지 못했다. 이번 예제는 충돌 없이 열 수 있는 꽃잎 순서로 이어갔다. 모든 네 꽃잎의 연속 완성과 이후 형태 변환은 별도 검증이 필요하다. 탐색 범위를 무작정 늘리거나 충돌을 끄는 방식으로 처리하지 않았다.
