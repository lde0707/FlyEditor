# 네 번째 점 선택 유지 수정

2026-11-11. FoldingDesk.PickFlank는 네 번째 클릭을 받았어도 CompleteFourPoints가 실패하면 rightFlank를 -1로 되돌렸다. 클릭 인식과 접기 가능성을 혼합한 상태 처리 문제였다.

수정: FourPoint 선택 후 계획 실패 시 ReviewFourPoints 상태로 이동한다. 네 점과 연결선을 유지하고 1~4 순서를 표시한다. 다른 점 클릭은 4번 교체, 선택한 점 재클릭은 기존 방식대로 해제한다. 불가능한 조합에서는 드래그가 기존 힌지 열기로 전환되지 않는다. 명시적 겹 재선택은 네 점이 해당 면에 모두 놓일 때만 다시 연결하여 접기 계획을 검사한다. 물리/충돌 계산은 변경하지 않았다.

검증: Unity 6000.5.3f1 컴파일. 48개 시점/선택순서에서 네 번째 점 보존, 해제/재선택, 차단 중 드래그 안전성, 겹 변경 시 선택 보존 검사 통과. 테스트용 저장을 격리한 Play Mode에서 새 종이를 4번 접은 후, 화면 좌표 입력으로 실패 조합 선택/해제/재선택/드래그 차단/빈 공간 초기화/성공 조합 재선택 및 5번째 꽃잎 접기까지 검증했다. input.jsonl과 캡처는 해당 실제 입력 실행이다. 48개 경우 모두 접힌다는 뜻은 아니다.

선택 순서는 화면 아래/위에 고정되지 않는다. 종이를 회전하면 움직일 끝과 기준 끝도 화면에서 달라진다. 이전 안내의 화면 방향만으로 현재 사용자의 정확한 재질 꼭짓점을 단정할 수 없었다. 접기 계산 실패를 점이 선택되지 않는 현상으로 보이게 하던 문제는 수정했으며, 지원되지 않는 임의 조합은 표시와 안내를 남긴다.

회귀 검사: FourHandleSelectionProbe.Run. FLYEDITOR_PLAYER_RECIPE 환경 변수는 Docs/OrigamiAudit/crane-player-2026-11-11/recipe.json을 지정한다. 앞의 4번 접기까지만 테스트 초기 상태로 읽는다. 이는 별도 실제 입력 검증과 구분된 상태/선택 검사이다.
