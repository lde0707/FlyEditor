# 면 선택 일관성과 키패드 시점 검증 · 2026-11-12

## 발견한 조건
1. 두 점 이후 기준점 가까이를 클릭하면 PointPress로 들어가 면 선택이 아닌 세 번째 점 선택이 됐다. 이제 기존 두 점의 선택/해제는 유지하고, 나머지 기준점 위 클릭은 면 클릭이다. F로 세 번째/네 번째 점 선택 상태에 들어간다.
2. 이전에 명시적으로 고른 면이 현재 보이는 면과 다르면 SelectedFace가 클릭을 거부했다. 새 클릭은 항상 가장 앞의 보이는 면으로 결정한다. 기존 면 선택은 이미 만든 접기 범위에만 적용한다.
3. 학을 두 번 접은 비스듬한 시점에서 테두리 클릭이 부동소수점 오차로 허공이 되어 점 선택이 지워졌다. 작업대 화면 좌표 기준 최대 2픽셀 안에서 실제 종이 경계로 보정한다.
4. 두 번째 점 선택 중 공유 꼭짓점을 숨은 다른 면으로 재지정할 수 있었다. 보이는 재질의 점인 경우에만 다시 연결한다. 모서리 바로 안쪽 면의 가시성도 확인하여 두께 때문에 드러난 숨은 겹의 끝점이 우선되지 않게 했다.
5. 면 선택을 접기 계획 생성 성공에 종속시켜, 연결이나 충돌 때문에 회전이 불가능하면 면도 선택되지 않았다. 이제 선택 상태와 회전 가능 여부를 분리한다.
6. 면 선택 직후 0도인 상태에서 F가 무시됐다. 이제 각도를 움직이기 전에는 정상 선택/접기 제한 양쪽 상태에서 모두 점을 추가할 수 있다.

## 현재 조작과 표시
- 점 두 개 → 선 → 선 양쪽의 보이는 면 클릭. 다른 쪽 클릭으로 선택 변경 가능(각도 0도).
- 초록색: 실제 이동 계획이 생성된 영역. 드래그/각도 조절/C 밀착 접기.
- 노란색: 영역은 선택됐으나 추가 연결 계산, 서로 다른 면 각도, 면 밖의 축, 양쪽 접촉 중 하나가 회전을 제한함. 화면에 이유와 다음 조작을 표시한다. 임의로 아래 겹을 가져오거나 충돌을 해제하지 않는다.
- F: 점 2개 추가. 이미 각도를 움직였다면 먼저 0도로 되돌리거나 접기를 완료한다.
- 시점: 키패드 1 정면 / 3 오른쪽 / 7 위. Ctrl+1/3/7은 반대편. 9는 현재 시점 반대편, .은 화면 맞춤. 4/6 및 2/8은 15도씩 회전한다.
- 뒤로 가려진 점의 선택은 시점 변경 시 해제한다. 면이 완전히 옆으로 보이는 고정 시점에서는 그 면의 점을 숨긴다.

## 검증 결과와 증거 범위
- 학 16단계 기록 2종을 엔진으로 재생: 총 32단계, 매 단계 면적/재질 연결부 검사 및 저장 재현 통과. 이것을 새 플레이어 입력으로 학 두 개를 처음부터 완성한 것으로 표현하지 않는다.
- 0/2/4/6/8/10/13/16단계 × 위/아래/비스듬한 앞뒤 시점 × 두 점 순서 × 두 축 방향에서 보이는 면을 선택.
- 446개 면 선택 모두 선택 상태 성립: Ready 150, NeedsHinges 246, ContactBlocked 50. 66개의 가려짐/너무 작은 영역/퇴화 표본은 제외되어 모든 가능한 접기를 보장하지 않는다.
- 선택한 끝점 가시성 512개 확인. 두 점 순서를 바꾸어도 숨은 면으로 재지정되지 않았음.
- 앞뒤 꽃잎 4개 경로, 148자세 및 겹 선택 8개 검사 통과.
- 기존 영역 일치 5사례/겹 122자세, 날개 64경로/3968자세, 완전히 접힌 날개 16경로, 가장자리 맞추기 8사례/368자세 검사 통과.
- 여섯 고정 시점의 방향과 면이 보이지 않는 옆 시점의 점 숨김 검사 통과.

## 실제 입력 확인
별도의 Unity 테스트 프로젝트에 Input System 마우스/키보드 이벤트를 전달했다. 사용자 저장 파일은 수정하지 않았다.
- input/: 기준점 위 면 클릭 → 각도 조절 진입, 위 모서리 선택, 1/3/7 및 Ctrl 반대 시점, 9 반전, . 맞춤, 같은 선의 양쪽 선택. 제한된 쪽은 노란색 안내, 반대쪽은 정상 선택.
- final-input/: 접기 제한 상태의 F, 정상 각도 0도 상태의 F 모두 LeftFlank 전환. 위 고정 시점에서 네 점 가장자리 맞추기 180도 완료(6 → 7), 되돌리기.
- PNG는 실제 Unity 화면/RenderTexture이며 합성 이미지가 아니다.
