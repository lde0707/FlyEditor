# 저장된 종이의 꽃잎 접기 검증 (2026-11-11)

사용자가 적용·저장한 실제 4회 접기 데이터를 별도 Unity 검증 프로젝트에서 복원했다. 원본 사용자 저장 파일은 수정하지 않았다. 검증 시작 상태는 starting-paper.json, 180도 접은 결과는 result-paper.json이다.

## 확인한 원인과 변경
- 점 강조는 13 표시 픽셀, 클릭은 8 픽셀로 판정해 가장자리에서 강조된 점이 선택되지 않을 수 있었다. 점 선택 중 판정을 13으로 통일했다.
- 4점 선택에서 1은 이동할 끝점, 2는 기준점이다. 실제 저장 상태에서 이를 반대로 고르면 연결된 안쪽을 들어 올리는 요청이 되어 주변 겹에 막힌다. 네 점을 버리지 않고 1·2 역할을 교환하는 버튼과 T 키를 추가했다.
- 1 이동 / 2 기준 라벨로 역할을 구분한다. 사용자의 점 순서를 자동으로 바꾸거나 충돌을 무시하지 않는다.

## 실제 입력 검증
starting-paper.json을 격리된 임시 세이브로 로드한 뒤 Unity Input System 마우스·키보드 이벤트로만 조작했다. 저장 상태 로드는 시험 준비이며, 새 정사각형부터 전 과정을 접었다는 의미는 아니다.

input.jsonl: 열기 → 우클릭 시점 회전 → 반대 순서 4점 선택 → T로 1·2 교환 → 드래그 50도 → 125도 → 180도 → 놓기. 접기 수 4에서 5로 증가했다. 01~05 PNG는 실제 게임 작업대 RenderTexture 캡처이며 selection-ui.png는 게임 화면 전체다.

## 자동 회귀 검사
SavedPetalInteractionVerification.Run, FLYEDITOR_PLAYER_RECIPE에 starting-paper.json 절대 경로 지정.
- 앞/뒤 × 원래 순서/교환: 4개 사례
- 실루엣 바깥 10 표시 픽셀에서 네 번째 점 클릭 유지
- 각 사례 0~180도 5도 간격, 총 148 자세: 충돌 검사 및 면적/연결 검증
- 고정된 반대 겹 안쪽으로의 움직임 차단
- 저장 재생과 되돌리기

범위: 이 저장 상태의 꽃잎 접기를 검증했다. 모든 임의 종이 상태의 꽃잎 접기, 종이학 전체 완성을 이번 검사로 보장하지 않는다.
