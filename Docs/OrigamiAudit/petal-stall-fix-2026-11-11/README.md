# 꽃잎 접기 3도 부근 정지 수정

2026-11-11. 사용자 설명과 유사한 정지 조건을 엔진에서 재현했다. 사용자 실행 중인 종이/네 점의 정확한 저장 상태는 확보하지 못했으므로 동일한 원인이라고 단정하지 않는다.

## 재현과 원인
실제 입력으로 생성했던 4회 접힌 정사각형에 꽃잎용 네 점을 적용하고, 오른쪽 제어점의 재질 좌표를 (0.01, 0.01)만 이동했다. 원래 점은 꽃잎 계산으로 -180도까지 움직이지만, 작은 오차가 있는 점은 꽃잎의 양옆 연결 변과 일치하지 않아 인식에 실패했다. 이후 일반 모서리 변형 계산으로 넘어가 -3.779297도에서 멈췄다. 네 점 선택을 유지하는 이전 수정만으로는 해결되지 않는 계산 경로 문제였다.

## 공통 수정
PaperCornerPull.Create에서 원래 꽃잎 인식이 실패하면, 선택점 근처에 존재하는 실제 재질 모서리를 찾는다. 보정 범위는 종이 짧은 변의 0.5%이며, 실제 모서리만 후보로 사용한다. 화면상 겹침으로 무관한 면을 합치지 않는다. 보정 후 꽃잎의 재질 연결 구조가 성립할 때만 그 계산을 사용한다. 멀리 떨어진 자유 선택점은 유지한다. 보정된 FoldStep은 미리보기와 저장/재실행에 동일하게 사용한다. 충돌, 고정 겹, 면적, 연결부 검사를 생략하지 않았다. 도안 이름이나 단계 번호를 런타임에서 참조하지 않는다.

## 검증
- 동일한 (0.01,0.01) 오차 입력: 수정 전 -3.779297도, 수정 후 -180도.
- 앞뒤 꽃잎 48개 근접 모서리 오차 사례: 5도 간격 전 구간, 역방향 되감기, 면적·재질 연결부, 완료/실행 취소/JSON 재실행 통과.
- 고정 겹으로 파고드는 반대 방향은 여전히 차단. 보정 범위 밖의 점은 임의로 바꾸지 않음.
- 기존 꽃잎 8개, 주머니 8개, 네 점 접기 12개 회귀 시퀀스 통과.
- 별도 Play Mode 실제 입력: 새 종이에서 4회 접고 네 점 선택 후 C/E 없이 드래그만으로 47→102→180도, 5번째 접기 완료. 이 입력 검증은 기본 네 점 조작 검증이며, 미세 오차 자체의 재현은 위 엔진 테스트에서 수행했다.

## 사용
이미 3도 부근에서 드래그를 놓아 접기가 적용됐다면 Z로 그 마지막 접기를 한 번 되돌리고 네 점을 다시 선택한다. 1번 끝을 기준점 방향으로 드래그한다. 현재 종이가 이 재현과 다른 방식으로 접혀 있거나 점이 허용 범위보다 크게 어긋난 경우까지 모두 해결했다고 주장하지 않는다.
