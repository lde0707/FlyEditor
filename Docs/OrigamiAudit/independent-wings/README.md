# 중앙 접기 후 두 날개 개별 펼치기 수정

## 재현과 원인

사용자가 첨부한 사진의 유형을 기본 기수/두 번 좁힌 기수 → 중앙 180도 접기 → 윗날개/아랫날개 펼치기 순서로 재구성했다. 플레이어의 저장 파일은 수정하지 않았다. 사진 자체에는 접기 레시피가 없으므로 플레이어의 메모리 상태를 그대로 복사한 테스트는 아니다.

기존 `connectedPanel` 경로는 재질상 이어진 조각을 따라 이동 대상을 확장했고, `MovesOtherPlyAt`은 이 경로의 반대 겹 검사를 건너뛰었다. 중앙 접합부를 가로지르는 약간 기울어진 선에서 반대 날개까지 이동 대상에 들어오는 것을 재현했다. 한편 정상적인 평행 날개 접기에서도 바깥 면 두 조각만 선택되어 같은 날개 안의 나머지 조각에 막히는 경우가 있었다.

## 공통 처리

- 새 `separateFoldSides` 선택은 앞선 평평한 접기의 **원래 종이 좌표상 소속**을 추적한다. 현재 높이나 앞/뒷면 색으로 날개를 구분하지 않는다.
- 선택한 면과 연결된 같은 날개의 조각은 함께 움직이고, 중앙 접기의 반대쪽 날개는 고정한다.
- 새 접는 축과 평행한 이전 접힘을 이용한다. 자유 클릭의 오차를 위해 5도 이내를 허용하며, 관계없는 이전 모서리 접기를 날개 경계로 사용하지 않는다.
- 이동 중인 면이 다른 날개 쪽의 접합부까지 연결되면 반대편을 자동 추가하지 않고 해당 단일 회전을 거부한다. 종이를 찢거나 충돌을 무시하지 않는다.
- 양쪽의 이동 범위는 `PaperSheet.Plan`에서 계산하므로 미리보기·드래그·확정·저장 재생에 같은 규칙이 적용된다.
- 접기 기록을 복제하는 계획용 작업에도 이력 스냅샷을 유지한다. 영역 계산은 현재 종이와 선택 축이 같을 때 재사용한다. 성능 향상 수치를 주장하는 변경은 아니다.
- 0도 미리보기 상태에서도 `1`/`2` 선택 전환이 버튼과 동일하게 동작한다.
- 예전 저장 레시피는 새 필드의 기본값이 false여서 종전 재생 동작을 유지한다. 기존 종이에 새로 선택해 접는 동작부터 새 규칙이 적용된다.

## 검증

`WingSideVerification`:

- 기본/두 번 좁힌 기수, 4가지 회전 방향, 위/아래 어느 날개부터 시작하든 16개 연속 접기 사례.
- 992개 중간 자세에서 종이 면적, 모든 재질 접합부, **반대 날개의 모든 재질 꼭짓점 위치** 검사.
- 아래쪽을 향해 파고드는 접촉 차단 유지.
- 부분 각도 저장 재생, 한 단계 되돌리기, 다시 접기, 계획 복사본의 독립 이력 검사.
- 기존 반대 날개 동반 이동 재현 및 새 선택에서 거부하는 회귀 검사.
- 기존 면 개별 방식으로 중앙을 접은 저장 이력도 지원하는지 검사.

`WingPlyInputPlay`:

- 실제 Unity Input System 점 선택, 전체/개별 전환, 면 선택, 두 날개 드래그 검사.
- 아랫면 가시성을 위해 카메라 각도는 테스트 코드로 아래쪽으로 배치한다. 종이 조작은 실제 포인터/키 입력을 사용한다.
- 선택하지 않은 날개 고정, 재생, 되돌리기와 편집 취소를 확인한다.

기존 접기 회귀 및 실행 결과는 `validation.txt`에 기록한다. `input/` 이미지는 Unity 작업대에서 직접 렌더링한 결과다.

## 사용

두 점으로 날개 선을 정한 뒤 `면 개별 [2]`에서 윗날개를 클릭하고 드래그한다. 반대 날개는 시점을 돌리거나 `다음 겹 [Tab]`으로 선택한다. 접는 선이 중앙 접합부를 가로질러 반대 날개까지 묶어야 하는 경우에는 자동으로 같이 끌고 가지 않는다. 이 경우 선을 날개 쪽으로 옮겨야 한다.
