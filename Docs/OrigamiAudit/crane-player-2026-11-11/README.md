# 플레이어 입력 종이학 검증 — 2026-11-11

## 결과와 증거 범위
새 정사각형 종이에서 16번 접어 목·꼬리·부리·양 날개를 만들었다. `steps/00.png`부터 `16.png`까지는 실제 Unity 종이 작업대 RenderTexture 캡처이다. `full-ui.png`는 실제 게임 UI 전체 화면이다. 합성 또는 이미지 생성 결과가 아니다.

마우스/키보드 이벤트를 Unity InputSystem에 넣어 플레이어와 같은 입력 처리 함수를 거쳤다. 사람이 직접 손으로 조작한 녹화라는 뜻은 아니다. 생성 중 PaperSheet.ApplyStep, 메시 교체, 접기 각도 강제 설정, 레시피 주입은 하지 않았다. 관찰용 reflection은 좌표 변환과 상태 읽기·캡처에만 사용했다. 사용자 연구 포인트/기체 저장은 별도의 임시 저장 경로로 격리했다.

**완성 범위:** 납작한 몸통의 학. 몸통을 부풀리는 마지막 입체화는 아직 지원하지 않는다. 모든 종이접기 도안이 가능하다는 검증은 아니다. 일부 주머니·겹 선택에는 카메라 회전과 명시적인 면 선택이 필요하다.

## 플레이어 조작 순서
- 초기 두 번: 두 끝점 선택 → 전체 겹 모드(1) → 움직일 면 선택 → 접기(C).
- 주머니: 펼칠 변 선택 → 끌어 벌리기 → 마지막 각도 수정(E) → 완전히 접기(C). 반대쪽으로 회전해 반복.
- 꽃잎: 움직일 끝점과 멈출 점 선택 → 점 추가(F) → 좌우 접힘점 선택 → 끝점 드래그. E/C로 완전히 닫기. 뒤에서도 반복.
- 목/꼬리 좁히기: 새 면을 V로 명시적으로 고른 뒤 네 점으로 가장자리를 중앙으로 정렬. 앞뒤 양쪽 네 번.
- 몸통: 중앙선 기준 반 접기.
- 목·꼬리: 끝점과 멈출 점으로 안쪽 뒤집어 접기. R로 꺾이는 방향 선택, 끝점을 멈출 점 쪽으로 드래그.
- 부리: 목의 위쪽 끝과 짧은 멈춤점 선택 후 뒤집어 접기.
- 날개: 날개 자체를 가로지르는 두 점 → V로 그 날개 선택 → 면을 드래그해 약 90도. 반대쪽으로 회전해 나머지 날개 반복.

각 단계의 실제 화면 좌표와 눌림/해제는 `input.jsonl`에 있다. paper/orbit 좌표는 1280×900 종이 카메라 픽셀 기준이며 screen 좌표는 이 실행의 644×884 Game View 기준이다. 다른 해상도에서 그대로 입력하면 특히 초기 UI 클릭과 회전량이 달라질 수 있다.

## 발견하고 수정한 공통 문제
1. 겹을 바꿔도 첫 번째 점이 이전 겹을 참조해 네 점 접기가 잘못된 면으로 이어졌다. 선택한 보이는 면 위에 있는 핸들만 다시 연결한다. 종이 메시/재질 꼭짓점을 합치지는 않는다.
2. 과거의 반 접기 이력으로 날개 소유권을 분리하는 규칙이 가로지르는 새 날개 접기까지 막았다. 기존 접힘에 가까운 방향의 겹 펼치기는 기존 소유권을 유지하고, 횡방향 접기는 선택한 재질 연결부에서 움직일 가지를 찾는다. 방향 구분은 45도 기준의 일반 규칙이며 도안 이름/단계를 참조하지 않는다.
3. 날개를 고르고 몸통의 멀리 떨어진 선을 사용하면 몸통 가지 전체가 움직이는 경우가 있었다. 횡방향 개별 접기는 선이 선택한 면을 실제로 가로지를 때만 허용한다.
4. 방향이 달라졌는데 겹 분리 캐시가 재사용되지 않도록 접는 축도 캐시 키에 포함한다.

충돌/면적/연결부 검사를 끄지 않았다. 새로운 일반 물리 시뮬레이터를 완성한 것은 아니다.

## 검증
- 실제 입력으로 새 종이 → 16단계 생성. 입력 로그 및 각 단계 캡처 보존.
- 마지막 안전 검사 추가 후, 입력에서 얻은 16단계 레시피를 엔진으로 다시 실행하여 동일 결과·면적·모든 재질 연결부·저장 재현·마지막 날개 실행 취소/재실행 검사 통과. 이 추가 검사는 입력 생성 증거와 별도이다.
- 첫 날개: (0,0) 꼭짓점 3.880566 이동, 반대 (11,11) 꼭짓점 0 이동.
- 둘째 날개: (11,11) 꼭짓점 3.880565 이동, 먼저 펼친 (0,0) 꼭짓점 0 이동. 안쪽 표본점도 각각 확인했다. 단위는 종이 엔진 내부 길이.
- 기존 날개 검사 64개 시퀀스/3968 자세, 추가 180도 접힘 16개 시퀀스 통과.
- 런타임 변경은 FoldingDesk.cs, PaperSheet.cs 두 파일이다. 다른 작업은 보존했다.

원본 입력 기록에는 시행착오도 남겨 두었다. 명령 46–47의 낮은 몸통 축 시도는 48에서 취소했다. 갤러리는 최종 채택된 단계만 사용한다. `manifest.json`은 단계별 원본 명령 번호와 이미지 SHA-256을 기록한다. `recipe.json`은 결과 관찰용 저장이며 이 파일을 주입해 캡처를 만들지 않았다.

`verification/CranePlayerSession.cs`는 별도 검증 프로젝트에서 사용한 입력·캡처 도구 원본이고, `CraneInputResultVerification.cs`는 결과의 후속 엔진 검사다. 후속 검사는 FLYEDITOR_PLAYER_RECIPE 환경 변수를 recipe.json 경로로 지정해 실행한다. 실행 로그는 verification/unity.log에 있다.
