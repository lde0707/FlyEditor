# 겹 식별·선택선 분할 1차 개선 — 2026-11-12

이번 범위는 재료 영역의 런타임 식별, 실제 접힘에서 얻은 겹 경계, 선택선으로 잘린 조각의 원본 소유권, 윗날개 단독 이동이다. 자유 곡면·자동 보조 접힘·새 스냅샷 저장 엔진 전체를 완성한 것은 아니다.

## 확인한 원인과 수정

- 기존 `LastFoldPartition`은 `cornerPull` 기록을 건너뛰었다. 네 점의 변 맞추기는 내부적으로 일반 회전 접기인데도 마지막 포개기의 경계가 누락돼 더 오래된 경계를 사용했다.
- 반 접기 → 네 점 변 맞추기로 다시 포개기 → 윗겹 선택에서 아랫겹이 이동 대상에 포함되는 사례를 재현했다. 원본 탐색에서는 8개 조건 중 5개에서 두 겹이 함께 ±60도까지 움직일 수 있었다.
- 실제로 수행한 rigid turn의 이동 재료와 축을 `PlyBoundary`로 기록한다. 어떤 입력·함수로 접었는지와 경계 기록을 분리했다. 일반 접기와 네 점 변 맞추기가 같은 규칙을 사용한다.
- 새로운 `materialPartition` 저장 옵션으로 새 선택에 적용한다. 과거 레시피의 선택 정책은 유지하며, 과거 레시피를 불러온 뒤 새로 선택할 때는 재구성한 실행 경계를 사용할 수 있다.
- `PaperMaterialRegion`은 변환·리베이스·층 번호 정리 중 재료 식별을 유지한다. 면 분할은 자식 영역으로 추적한다. `SurfacePoint`는 재료 좌표와 계보로 면 분할·변환·되돌리기 후에도 같은 재료점을 찾는다. 런타임 식별자는 현재 저장 포맷에 영구 저장되는 ID가 아니다. 권위 있는 상태 스냅샷 저장은 다음 단계다.
- 새 분할 경로는 자른 조각마다 원본 면 번호를 보관하고, 고정 조각을 그 번호로 구성한다. 위치·층·겹치는 면적을 다시 비교해 원본을 추측하지 않는다. 미리보기와 확정은 동일한 turn을 사용한다.
- 충돌 검사와 종이 연결 검사를 유지한다. 한 축으로 아랫겹을 고정한 채 움직일 수 없는 요청은 함께 끌고 가는 대신 거절한다. 이런 요청을 주변 휨·보조 접힘으로 해결하는 범용 계산기는 아직 다음 단계다.

## 회귀 검증

- 수정 전: `nested-ply-red.log`에서 `nested four-handle book carries untouched lower ply at -20/-0.2`로 실패.
- 수정 후: 중첩 포개기 선택선 20개 변형, 정상 윗날개 선택 가능 여부, 실제 초록색 메쉬와 이동 영역의 일치 검사.
- 재료 참조: 면 분할·회전·층 정리·planning copy·undo 후 같은 재료점 유지. 다른 종이의 참조는 거절.
- 새 정책: 기본/좁은 기체 × 회전 4방향 × 날개 순서 2가지 × 선택선 4종 = 64개 시퀀스, 512개 중간 자세. 반대 날개 고정, 면적·연결, 재생 검사.
- 기존 기준 검사: 꽃잎 8개, 뒤집기 16개와 관절 24개, 날개 64개/3968자세, 180도 날개 16개, 제트 8개/368자세 등. 각 결과는 로그의 자체 집계를 따른다.

## 실제 플레이어 입력 검증

자동화는 Input System에 화면 좌표의 마우스·키 이벤트를 전달한다. 선택 함수·접기 함수·각도 설정 함수를 직접 호출하지 않았다. 별도 observer는 재료 좌표와 위치를 읽고 사진을 저장한다. Computer Use는 사용하지 않았다.

### 새 종이에서 반 접은 두 겹

1. 종이접기 버튼 클릭, `Numpad7`로 위에서 보기.
2. 중앙 세로선의 양 끝 클릭 → 오른쪽 면 클릭 → `C`로 180도 밀착.
3. 포개진 종이 중앙 세로선의 두 점 클릭 → 왼쪽의 보이는 면 클릭.
4. 면을 위쪽으로 드래그하고 놓기: 104도. 선택점 순서를 뒤집고 되돌리기 후 재시도: 78도.

### 비행기 형태의 겹친 날개

시작 상태는 `plane-seed.json`의 5회 접기 레시피로 준비한 테스트 기체다. 이 준비 단계를 실제 플레이어가 처음부터 접었다고 집계하지 않는다. 시작 상태를 불러온 뒤의 선 선택·면 선택·날개 드래그는 모두 실제 입력이다.

1. 종이접기 버튼 클릭 → `Numpad7`.
2. 꼬리 쪽 변의 한 점과 기수 끝을 클릭해 날개 접힘선 지정.
3. 선 아래의 보이는 윗날개를 클릭.
4. 면을 위로 드래그해 78도에서 놓기.
5. `Numpad8` 두 번으로 비스듬히 확인.

## 실행과 증거

- `PlyPartitionVerification.Run`: 새 겹 식별/분할 회귀. 격리된 Unity 프로젝트에서 `-executeMethod FlyEditor.Editor.PlyPartitionVerification.Run`으로 실행하며, 완료 시 편집기를 종료한다. 사용 중인 실제 편집기에서 직접 호출하지 않는다.
- `PlyPartitionRegression.Run`: 위 검사와 기존 `OrigamiTechniqueBaseline`을 함께 실행하는 격리 프로젝트용 명령.
- `rectangle/`, `aircraft/`: 단계별 실제 Unity 렌더, UI 전체 사진, 입력 이벤트, 재료 좌표, 레시피.
- `player-measurements.json`, `plane-player-measurements.json`: 두 입력 사례의 측정값.
- `source-manifest.json`: 배포 소스 해시와 테스트 범위.
- 기존 사용자 저장 파일·연구 포인트는 테스트에 사용하지 않았다. 테스트용 진행 파일만 생성·정리했다.

## 남은 범위

- 선택된 윗겹을 접기 위해 주변 여러 관절을 동시에 휘게 하거나 보조 접힘을 생성해야 하는 동작.
- 곡선 접기, 복합 함몰, 드래곤 중첩 작은 꽃잎 등 전체 고급 기술의 지원 인증.
- 런타임 재료 식별과 연결 관계를 영구 상태 스냅샷으로 저장하는 새 저장 형식.
- 목표 PC에서 입력 지연·프레임 시간·할당량 측정. 이번 검사는 정확성 검증이며 성능 개선 수치를 주장하지 않는다.

최종 비행기 입력은 배포 소스로 다시 실행했다. 첫 자동 재실행은 화면 준비 전에 클릭이 전송되어 비행으로 진입했고, 접기 화면이 없는 상태의 관찰기가 예외를 냈다. 테스트 관찰기에 null 방어와 화면 준비 대기를 추가한 최종 재실행에서는 위 6개 입력 명령을 모두 정상 수행했다. 제품 엔진의 접기 함수는 이 보정에서 변경하지 않았다.
