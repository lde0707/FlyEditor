# 중첩 안쪽 뒤집기 개선과 재검사

검사일: 2026-11-11. Unity 6000.5.3f1.

## 변경

PaperPacketReverse에 부모/자식 접기 영역을 추가했다. 기존 접힌 영역 안에 새 끝부분 접기가 들어오면, 바깥 영역부터 분할한 뒤 부모의 현재 변환 위에서 자식의 양옆 힌지와 끝점 방향을 계산한다. 평평하게 닫힐 때는 중첩 깊이에 따라 겹 순서를 배치한다. 도안 이름이나 학 좌표는 런타임에 넣지 않았다.

기존의 서로 떨어진 뒤집기 경로는 유지했다. 연결부, 접촉, 잘못된 각도, 원본 상태 변경에 대한 검사는 제거하지 않았다. 제작 중인 게임의 저장 파일은 덮어쓰지 않았다.

## 통과한 검사

- 4방향 회전 × 2가지 면 탐색 순서 = 8가지. 2단 및 3단 중첩, 0~180도 연속 동작, 역방향 스크럽.
- 종이 면적과 연결부, 유한 좌표, 반대쪽 꼬리와 부모 힌지 위치 유지.
- 90도 중간 저장, 180도 저장, JSON 재생, 원본 참조까지 일치하는 되돌리기.
- 기존 묶음 뒤집기 8가지, 꽃잎·주머니·4점·열기·비행기 및 기체 성능 관련 회귀 검사.
- 실제 작업대 입력: 학 13단계 상태에서 끝점과 기준점 클릭 → 끝점 드래그 → 자동 중첩 뒤집기 → 앞뒤 드래그 → 180도 적용 → 재생 → 수정 취소 → 되돌리기.

## 세 종류 재검사 판정

| 대상 | 결과 |
|---|---|
| 종이비행기 | 새 종이부터 5회 적용, 양쪽 날개 및 재생 통과 |
| 꽃잎 접기 | 새 종이부터 기본형과 양면 꽃잎 6회 적용, 면적·연결부·재생 통과 |
| 학 | 이전에 막혔던 머리 중첩 뒤집기(14단계) 해결. 양 날개를 상부 힌지로 펼치는 16회 경로도 적용·재생 성공. 다만 추가 검사에서 더 낮은 허리선의 날개 접기가 막혀, 일반적인 학 도안의 최종 형태는 미완성 판정 |

학의 결과는 **머리 구간 해결 / 전체 도안 완성 미인증**이다. 단계 적용이 모두 성공했다고 최종 학 형태가 완성됐다고 판단하지 않는다. results/result.json에도 이 수동 형상 검수 결과를 반영했다. head-input.json은 실제 작업대 입력으로 만든 머리 접기의 재생 데이터다.

## 재현 자료

- `results`: 세 종류 단계별 엔진 데이터와 Unity 렌더
- `input`: 실제 작업대에서 머리를 접은 화면, `head-input.json`
- `NestedRegression.cs`: 일반 종이의 2~3단 중첩 회귀 검사
- `NestedInputPlay.cs`: 실제 점·드래그 입력 검사
- `ThreeFoldsImprovedAudit.cs`: 세 종류 엔진 경로 재실행
- `unity-four-system-nested-regression.log`, `unity-four-system-nested-input.log`: 통과 로그
- `unity-four-system-nested-wing-waist.log`: 남은 허리선 제약 기록

다음 개선 대상은 목·꼬리와 연결된 날개 뿌리에서, 단일 강체 회전으로는 막히는 낮은 허리선의 복합 변형이다. 현재 테스트는 모든 자유 접기 조합의 지원을 의미하지 않는다.
