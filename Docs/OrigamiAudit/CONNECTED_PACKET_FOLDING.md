# 연결된 면 묶음 뒤집기

2026-11-10 · Unity 6000.5.3f1

## 사용 방법

1. 작업대의 **연결 묶음 [4]** 버튼 또는 숫자 4를 선택한다.
2. 뒤집을 끝점과 같은 접힘축 위의 기준점을 일반 클릭한다. 고정 격자 및 Alt 조합은 사용하지 않는다.
3. 초록색으로 표시된 끝부분과 보조 접힘선을 확인한다.
4. 끝점을 기준점 쪽으로 끌거나 면을 클릭해 드래그한다. 진행 초반에는 묶음을 벌리고, 이후 안쪽으로 뒤집어 닫는다. 같은 드래그 중 반대로 움직이면 되돌아간다. 마우스를 놓으면 현재 상태를 적용한다.
5. Tab으로 겹을 바꿔도 연결 묶음 범위를 유지한다. 보이는 겹 [1]로 돌아가면 한 겹 선택으로 돌아간다. 빈 곳 클릭으로 선택 해제, Z로 되돌리기, E로 마지막 접기를 수정한다.
6. 두 점으로 계획을 만들 수 없으면 점 추가 [F]로 기존 4점 접기를 사용할 수 있다. 4점 처리는 기존 공통 연산이며 새 묶음 뒤집기의 임의 보조선 편집을 의미하지 않는다.

## 엔진 변경

- PaperPacketReverse: 원래 종이 좌표의 공통 가장자리를 따라 끝부분을 탐색한다. 화면에서 겹쳐 보인다는 이유만으로 서로 다른 부분을 하나로 취급하지 않는다.
- 접힘축 양쪽 면을 분할하고, 끝점에 연결된 부분을 찾아 묶는다. 몸통의 기준면을 고정하고 반대쪽 면을 벌리며, 양옆 보조 접힘으로 끝부분을 뒤집는다. 몸통 전체를 고정한다는 의미는 아니다.
- 이미 완전히 닫힌 동축 뒤집기가 있으면 그 이력과 원래 종이 좌표를 이용한다. 다음 끝을 접는 동안 이전 부분도 연결을 유지하며 움직이고, 완료 시 이전 끝의 위치를 복원한다.
- 각 접힘은 자기 기준점을 갖는다. 화면상 겹친 영역을 먼저 분리한 뒤 실제 연결 관계로 선별하므로 다른 끝부분을 덮어쓰지 않는다.
- 시작 자세가 현재 종이와 이어지는지, 원래 종이 이음매가 유지되는지, 중립면이 서로 가로지르는지 검사한다. 잘못된 점 좌표 및 지원하지 않는 중첩은 현재 종이를 변경하지 않고 거부한다.
- packetReverse / packetMaterialHandles 및 원래 종이 좌표를 FoldStep에 저장한다. 기존 저장은 이 플래그가 false이므로 이전 연산을 유지한다.
- 앞선 묶음의 원래 좌표를 저장하므로 매번 중간 이력을 재귀적으로 모두 재구성할 필요가 없다. 생성과 매 프레임 자세 계산을 분리한다. 성능 향상 수치는 측정하지 않았다.
- FoldMesh가 실제 선택된 끝부분을 강조하고, 초기 두 점도 계속 표시한다. 접기 UI는 기존 enum FSM에 선택 범위와 전이 처리를 추가했다.

## 검증 결과

- 4방향 × 앞뒤 앵커 선택 = 8사례. 0~180도를 3도 간격으로 검사하고 역방향 스크럽을 수행했다.
- 각 자세에서 면적, 유한 좌표, 중립면 이음매 및 몸통 기준점 고정을 검사했다. 이음매와 기준점 허용오차는 0.002이다.
- 바깥 몸통의 위아래 겹 순서 보존, 부분 적용·전체 적용의 JSON 저장 재생, 두 끝 연속 접기, 첫 끝 위치 보존, 두 번 되돌리기를 검사했다.
- NaN 및 범위 밖 각도 거부, 지원하지 않는 중첩 뒤집기 시 기존 상태 보존을 검사했다.
- Unity Input System으로 일반 클릭, 연결 묶음 미리보기, 앞뒤 드래그, 완료, E 수정·취소, Z 되돌리기, 빈 공간 해제, Tab 겹 변경, 한 겹 복귀, 4점 접기로의 전환과 실제 비행 기체 적용을 검사했다. 초기 종이 상태 준비는 API로 하고 조작은 실제 입력 이벤트로 수행했다.
- Petal / Pocket / FourPoint / RadialGather / PaperFolding 및 기존 기체 형상·잡는 위치·성능 계산 회귀 검사 통과.

## 학 재시도

기존 좁힌 학 기본형 10회 접기 → 몸통 넘기기 1회 → 목·꼬리에 해당하는 두 끝의 연결 묶음 뒤집기 2회 = **13회 접기**까지 진행했다. 각 끝은 8개의 면 조각으로 구성되며, 연속 동작과 저장 후 재생을 검사했다.

**학 완성은 아니다.** 이미 뒤집은 끝 안에서 머리를 다시 꺾는 중첩 뒤집기는 지원하지 않는다. 머리 완성과 날개를 펼친 최종 학 형상은 아직 검증하지 못했다. 이번 13회 검사는 엔진 API로 학 순서를 재현한 것이며 학 전체의 마우스 조작 완주 검사는 아니다.

## 남은 제한

- 현재 묶음 연산은 공통 접힘축과 기본 65도 보조 접힘 관계를 사용한다. 모든 임의 4점 구성이나 모든 입체 종이에 적용되는 일반 해법은 아니다.
- 중첩된 뒤집기, 서로 다른 접힘축이 만나는 복잡한 주머니는 추가적인 접힘 연결 구조가 필요하다.
- 중립면 기반 강체 회전과 별도 표시 겹 순서를 사용한다. 유한 두께의 굽힘 반경, 마찰, 종이 구김까지 푸는 물리 엔진은 아니다. 접촉 검사는 각도 샘플에 기반한다.
- 닫힌 여러 겹의 표면 표시에는 두께에 따른 간격이 생길 수 있다. 중립면 연결 검증과 표시 두께를 구분한다.

재현 메뉴: Tools → FlyEditor → Validation → Connected packet reverse.
학 입력 데이터: Docs/OrigamiAudit/crane-current/results/10-narrow.json.
실험 코드에만 도안 좌표가 있고 런타임에는 학 이름이나 도안 전용 좌표가 없다.
