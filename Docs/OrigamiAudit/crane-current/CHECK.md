# 현재 기능의 종이학 재검증

검사일: 2026-11-10. 판정: **미완성**.

실제 FlyEditor 프로젝트의 비행/접기 런타임 C# 27개가 검사 프로젝트와 일치하는 것을 확인했다. Unity 6000.5.3f1에서 현재 UI가 사용하는 adaptiveCreases / coordinatedCreases / compactLayers 옵션을 적용했다. 검사 도안은 기존에 보관한 California Museum 종이학 도안이다. 예비 접기는 생략했다.

## 결과

| 구간 | 결과 |
|---|---|
| 사각 기본형: 모양 접기 2회 + 주머니 눌러 펴기 2회 | 통과 |
| 앞면·뒷면 꽃잎 접기 | 통과 |
| 네 가장자리를 중앙으로 좁히기 | 통과 |
| 목·꼬리를 위로 올리는 안쪽 뒤집기 | 막힘 |
| 머리 접기·날개 펼치기·최종 학 형태 | 선행 단계 실패로 미검증 |

총 10회 적용. 도안 15번의 좁힌 기본형까지 진행했고 16~17번 목·꼬리에서 막혔다. 완료된 단계에서는 종이 면적, 중립면 이음매, 유한 좌표, 저장 후 재생을 검사했다. 엔진 검사 프로세스의 정상 종료는 학 완성을 뜻하지 않는다. result.json의 craneCompleted는 false다.

## 막히는 지점

목과 꼬리의 각 끝점을 대상으로 자유 위치 63개와 기존 형상의 위치를 합쳐 68개/69개의 접힘 기준을 검사했다. 그대로 둔 상태와 책장처럼 한 번 넘긴 상태 모두에서 PaperInsideReverse가 유효한 계획을 생성하지 못했다. 반대 방향 책장 접기는 차단됐다.

현재 PaperInsideReverse는 서로 맞닿는 두 패널로 free tip을 만들고 두 패널 각각에 끝점과 기준점이 함께 있어야 한다. 좁힌 기본형처럼 여러 면 조각과 겹이 연결된 끝부분을 하나의 접힘 묶음으로 다루는 기능이 부족한 것으로 판단한다. 자유점 선택만으로 해결되는 문제는 아니다.

다음 개선 대상은 연결된 여러 면을 묶은 목·꼬리의 안쪽 뒤집기다. 묶음의 접힘축, 양옆 보조 접힘, 고정 몸통과 이음매, 겹 충돌을 함께 풀어야 한다. 특정 학 좌표나 완성 메시로 교체하지 않고 공통 연산으로 해결해야 한다.

## 검증 범위

이번 검사는 실제 접기 엔진 API로 도안 순서를 재현하고 Unity 메시를 렌더한 검사다. 마우스로 모든 단계를 직접 수행한 UI 완주 검사는 아니다. 제한된 위치/경로를 검사했으므로 모든 가능한 우회 접기 경로가 불가능하다는 증명도 아니다. 표준 도안 순서가 현재 기능으로 완주되지 않는 것을 확인했다. 런타임 코드는 이번 검사에서 변경하지 않았다.
