# 선 한쪽의 보이는 면 전체 선택 — 2026-11-13

## 바뀐 조작
- 기본 [1]: 점 두 개로 선을 만든 뒤 한쪽의 아무 면을 클릭한다. 해당 쪽에서 보이는 파란 면·흰 면들을 함께 선택한다. 이어서 드래그하고 놓으면 접힌다.
- [2] 전체 겹: 선 한쪽의 가려진 겹과 화면 밖의 면까지 포함한다.
- V: 클릭으로 개별 면 선택, 드래그로 박스 선택. 필요한 경우에만 범위를 좁히는 도구다.
- Esc: 취소, Z: 완료된 접기 되돌리기.

초록색은 실제로 접히는 전체 영역이다. 노란색은 선택했지만 연결·충돌 또는 추가 접힘 때문에 현재의 한 축 회전으로 실행할 수 없는 요청 영역이다. 연결되지 않은 겹을 임의로 따라 움직이거나 충돌을 무시하지 않는다.

## 원인과 공통 수정
기존 기본 클릭은 클릭한 조각을 기준으로 단일 면/과거 접힘 소유 범위를 검사했다. 선이 다른 연결된 면을 가로지르는 경우, 클릭한 파란 조각에는 선이 직접 지나가지 않는다는 이유로 선택이 거부됐다. 재현에서는 흰 면까지 포함한 60.5 면적이 접혀야 했으나 이동 영역이 0이었다. visible-side-red3.log에 보존했다.

- 기본 클릭과 마우스 미리보기가 선 한쪽의 보이는 source face 집합을 먼저 수집한다. 파란 조각과 흰 조각 중 어디를 클릭했는지로 범위를 제한하지 않는다.
- 클릭과 박스 선택은 같은 ResolveRegion 계획/표시 경로를 사용한다. 저장되는 FoldStep.selectedFaces도 실제 계획과 일치한다.
- 화면/카메라가 달라지면 미리보기 집합을 다시 계산한다. 기존 임시 선택과 클릭 후 결과가 달라지는 일을 줄였다.
- 전체 겹의 선 한쪽 선택은 박스·화면의 제한을 받지 않는다. 박스는 사용자가 그린 사각형 범위를 계속 따른다.
- 개별 면은 명시적인 V 클릭 경로로 유지했다. 기본 모드와 안내도 구분했다.
- 접기 불가능한 요청도 여러 면에 걸쳐 표시하도록, 각 면의 좌표계에 같은 공간상의 선을 변환한다. 물리 계획이 실패해도 요청한 면 선택을 숨기지 않는다.

도안 이름, 단계 번호, 특정 face index에 대한 런타임 처리는 추가하지 않았다. PaperSheet의 연결·충돌 계산을 우회하지 않았다.

## 검사 결과
- VisibleSideSelectionVerification: PASS 73건 / 320개 자세.
  - 수직/비스듬한 선, 파란 면/흰 면 클릭, 점 순서 반전, 종이 4회전, 원근/직교.
  - 보이는 겹/전체 겹, 앞/뒤 시점의 겹친 책 모양. 기본 보이는 겹 선택에서 완전히 가려진 다른 겹 고정 확인.
  - 초록색과 실제 이동 면적, 전체 종이 면적/이음새, 충돌, 저장 재생, 되돌리기, V 개별 선택 유지.
  - 비스듬한 선 면적 허용 오차 0.03/121은 화면에서 찍은 점의 작은 스냅 오차를 포함한다. 클릭한 조각 하나만 움직이는 실패와는 구분되는 작은 범위다.

- BlenderFoldView: PASS. 원근 선택 및 near-plane 검사 포함.
- WholeSheetFold: PASS 8건 / 48개 자세.
- 실제 플레이 입력: 16개 캡처. 서로 다른 면의 점을 이은 비스듬한 선에서 파란 면/흰 면의 마우스 미리보기·클릭이 같은 이동 영역을 만들었다. 함께 26° 접고 저장/재생했다. 고정된 반대 영역은 독립 원본 재질 좌표 검사로 확인했다.
- 실제 렌더링 초록 면적과 실제 이동 면적을 비교했다. Esc, Z, 개별/박스 선택의 구분도 확인했다.
- core-final/result.json: 최종 공통 기술 회귀 결과.

사진의 현재 미저장 접기 이력은 확보하지 못했다. 편집기 로그의 4회 접기 저장 사본도 사진의 형상과 달랐다. 따라서 실제 입력 검사는 같은 실패 조건(선이 여러 파란/흰 면에 걸치고 클릭한 조각 바깥에서 다른 면도 분할해야 하는 상황)을 갖춘 공통 2회 접기 시작 상태에서 수행했다. 첨부 상태 그대로의 완성 모델 검증을 뜻하지 않는다. 도움말 문구를 정리한 뒤 최종 소스로 공통 회귀를 재실행했다.

사용자 진행 파일은 변경하지 않았다. 테스트 시작 상태는 별도 임시 저장 경로를 사용했다.
