# 현재 시스템으로 비행기·꽃잎·학 접기

검사일: 2026-11-11. Unity 6000.5.3f1.

| 대상 | 결과 | 적용 횟수 | 확인 범위 |
|---|---|---:|---|
| 기본 종이비행기 | 완성 | 5 | 새 정사각형에서 두 모서리, 동체, 위·아래 날개까지 실제 Input System 클릭·드래그. 저장 후 재생 일치. |
| 꽃잎 접기 | 앞·뒷면 성공 | 6 | 2회 모양 접기 + 2회 주머니 눌러 펴기로 기본형을 만들고 양면 꽃잎을 접음. 별도 입력 검사에서 기본형을 불러와 4점 선택, 90도 열기, 끝까지 눌러 펴기를 확인. 완성된 꽃 모형을 뜻하지 않음. |
| 종이학 | 미완성 | 13 | 기본형, 양면 꽃잎, 네 변 좁히기, 책장 접기, 목·꼬리 뒤집기까지 적용. 머리 뒤집기에서 중단. 최종 날개와 학 실루엣은 미검증. |

## 학에서 막힌 부분

목 끝의 기존 뒤집기 영역 안에 더 작은 뒤집기를 만드는 중첩 동작이다. 끝점에서 안쪽으로 잡는 기준 위치 7종(0.35, 0.5, 0.75, 1, 1.25, 1.5, 2)과 묶음/일반 뒤집기 2종을 모든 해당 면에서 검사했다. 이 경로에서는 유효 계획이 생성되지 않았다. 실패 시 기존 13회 접기 상태가 유지되는 것을 확인했다. 모든 우회 접기 방법이 불가능하다는 판정은 아니다.

## 실행과 보존

현재 프로젝트 런타임 소스를 해시 비교하여 검사 프로젝트에 동기화했다. 현재 PaperSheet, PaperCornerPull, PaperInsideReverse를 호출했고 완성 메시 주입이나 도안 전용 런타임 보정은 하지 않았다. 예비 접기는 생략했다. 제작 중인 게임의 저장 데이터와 실행 중인 작업대는 변경하지 않았다.

`results`에는 단계별 실제 Unity 렌더와 재생 가능한 paperFolds JSON이 있다. `input`에는 실제 작업대 입력 검사 이미지와 그 결과 JSON이 있다. 학 전체는 엔진 API 경로 검사이며 마우스로 전 단계를 완주한 검사가 아니다. 꽃잎 입력 검사의 사각 기본형은 엔진에서 만든 데이터를 불러왔다.

- `results/result.json`: 대상별 완료 여부, 단계, 학의 막힌 조건
- `input/airplane-input.png`: 실제 작업대 입력으로 완성한 비행기
- `input/petal-input-midway.png`, `input/petal-input-flat.png`: 4점 입력으로 열고 누른 꽃잎
- `results/petal/final.png`: 양면 꽃잎 결과
- `input/crane-workbench-stopped.png`: 현재 13회 접기 결과를 작업대에서 다시 연 상태
- `source-manifest.json`: 검사에 사용한 런타임 소스 해시
- 두 Unity 로그: 엔진 순서 검사와 실제 입력 검사 구분

런타임 기능 수정은 이번 검사에 포함하지 않았다. 다음 개선 대상은 겹친 접기 영역 내부의 중첩 뒤집기다.
