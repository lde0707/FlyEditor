# 일반 플레이의 연구 웹

첫 비행을 마치면 다섯 후보가 열린다. 던지기 강화, 활공 효율, 자세 회복, 기체 내구, 수집 끌어당김이다. 구매 전 후보는 50% 불투명도로, 구매한 노드는 100%로 표시한다. 구매한 노드의 바로 다음 후보만 열리고, 같은 갈래의 다른 선택지도 계속 남는다. 모든 33개를 일반 플레이에서 한 번씩 구매할 수 있다. 원본 배치와 연결선은 [전체 설계 이미지](ResearchUI_v5/Dense_Web_33_Nodes_1920x1080.png)를 참고한다.

기존 던지기·활공·표면 저항·상승 효율 12개를 전부 구매한 저장에서는 첫 화면에 16개가 보인다. 기존 12개에 가속 아이템 강화, 자세 회복, 기체 내구, 수집 끌어당김이 추가로 열린 상태다. 저장 파일의 ID와 연구점을 사용한다. 개발자 모드에서 새 진행을 시험할 수 있다.

## 비행 효과와 조작

- 가속 아이템은 노란 마름모로 표시한다. 기본 접촉 시 속도 증가량은 2 m/s이며 세 노드가 각각 기본값의 15%를 추가한다. 기체의 최고 속도를 적용한다.
- 하강 가속은 하강 중 공기 저항을 28% 줄인다. 후속 노드가 발동 지연을 0.6초에서 0.2초로 줄이고 하강 후 1.25초간 효과를 이어 준다.
- 복숭아색 삼각 장애물에 부딪히면 감속하고 기체 자세가 0.85초 동안 흐트러진다. 자세 회복을 해금하면 Space로 회복하며, 후속 노드는 회복을 더 빠르게 하거나 사용 횟수를 늘린다.
- 기체 내구는 100부터 시작하며 노드당 10 증가한다. 충격 분산은 충돌 때 잃는 속도를 기본 손실량의 12%씩 줄인다. 내구 소진과 지면 접촉은 기존 정산 경로로 비행을 마친다.
- 종이 방패는 첫 장애물 충돌의 내구 피해를 막는다. 후속 노드는 방패 발동 시 감속을 절반으로 줄이고, 세 번째 노드는 비행당 방패 사용 횟수를 한 번 늘린다.
- 수집 끌어당김은 가속 아이템을 기체 쪽으로 이동시킨다. 기본 범위는 3m, 후속 범위는 5m다. 마지막 노드는 끌어당기는 속도를 9 m/s에서 18 m/s로 높인다.

각 효과와 소모 횟수는 비행을 준비할 때 구매 기록에서 읽는다. 아이템과 장애물은 같은 오브젝트를 앞쪽 경로에 다시 배치한다. 위 수치는 첫 플레이테스트를 위한 기본값이다.

아래는 초기 웹 적용 기록이다.

# InGame 연구 웹 적용

## 사용

1. `Assets/_Project/Scenes/InGame.unity`에서 Play를 시작한다.
2. 첫 비행을 마친 뒤 대기/착륙 화면에서 **연구 열기** 또는 **U**를 누른다.
3. 심볼을 선택하고 오른쪽 설명창에서 연구한다. **Esc / 비행으로**로 돌아온다.

## 적용한 화면

- 흰 배경과 옅은 파스텔 환경 이미지.
- 중앙 비행기 시작점, 고정 위치의 심볼 노드, 각진 연결선.
- 속도=살구, 활공=하늘색, 조종=라벤더, 생존=세이지.
- 선택=이중 테두리, 구매=체크+단계 채움, 최대 강화=계열색이 조금 진해짐.
- 오른쪽에 이름·현재 단계·실제 적용값·효과 설명·다음 비용·구매 버튼.
- 누르는 중/강화 완료/최대 단계의 구매 버튼 이미지.
- 저장 성공 후 0.21초의 비발광 모서리 피드백. 잠시 완료 버튼을 표시한 뒤 다음 비용 상태로 복귀.
- 화면 기준은 1920×1080이며 화면 비율에 맞춰 가운데 정렬한다.

## 실제 구현 범위

실제 비행 효과와 저장·구매가 구현된 A1 던지기 강화 / G1 활공 연습 / C1 조종 반응 세 종류를 표시한다. 이 셋은 첫 비행 후 모두 후보다. 연구점 부족은 후보를 숨기지 않으며 구매만 막는다.

나머지 17개는 위치·심볼·색상·설명·비용·선행 조건 데이터까지 연결했으나, 해당 게임 기능이 아직 없어 일반 플레이에서는 숨긴다. 새 기능을 구현하고 그 노드의 런타임 매핑을 추가하면 같은 뷰에서 확장한다. 실효과 없는 증강에 연구점을 쓰게 하지 않는다.

## 전체 20개 보기

Play 중 비행 대기 또는 착륙 상태에서 메뉴:

`Tools > FlyEditor > Preview Complete Research Web (Play Mode)`

전체 20개를 확인하고 선택할 수 있다. 미리보기임을 표시하고 구매는 전부 차단한다. **Esc / 비행으로**로 나가면 일반 모드로 돌아온다. Editor 전용 진입점이며 빌드에서 미리보기를 열 수 없다. 진행 데이터와 연구점은 변경하지 않는다.

## 구조

- `ResearchWebAssets.cs`: 직렬화 가능한 노드·계열·텍스처 데이터.
- `Assets/_Project/Data/ResearchWeb.asset`: 배경, 버튼, 단계별 PNG, 20개 노드 위치와 선행 조건. InGame 컨트롤러에 참조되어 빌드에도 포함된다.
- `ResearchWebView.cs`: Browsing → Purchasing → PurchasedFeedback → Browsing FSM. 상태 전이는 ChangePhase를 사용한다.
- `PaperFlightController.cs`: 기존 비행과 연구 화면 전환, 입력 차단, 실제 구매 메서드에 연결.
- `ResearchWebVerification.cs`: 에셋 참조 검사와 전체 웹 미리보기 메뉴.

리소스는 에디터 경로에서 런타임 로드하지 않는다. ScriptableObject에 직접 참조하며 이름·비용·효과는 이미지에 굽지 않는다. 표시 문자열·스타일은 선택/구매 때 갱신하고 비행 중 형상 평가나 웹 갱신을 반복하지 않는다.

## 검증

- Unity 6000.5.3f1 컴파일과 20개 노드·4개 계열·모든 단계/선택/구매 피드백 텍스처 참조 검사.
- 기존 비행 모델, 입력 게이트, 에너지 소모, 착륙·재시작·재발사 검사.
- 연구 비용 30/65/130, 잔액 부족, 단계 상한, 저장 실패 원자성, 재로드와 중복 보상 방지 검사.
- 실제 후보 3개, 숨긴 S1/X3 선택 거부, 전체 미리보기 20개, 미리보기 구매 차단과 원래 모드 복귀 검사.
- 사용자 저장 파일과 분리한 임시 저장 파일로 자동 Play와 구매 검사.
- 원본 Unity에서 연구 화면 열기, 활공 노드 선택, 실제 수치/단계 갱신, 전체 웹 미리보기와 X3 설명 표시를 직접 확인. 사용자 연구점은 쓰지 않았다.

초기 격리 에디터는 Unity 검색 인덱스의 시작 예외로 중단됐다. 검증 전용 진입점에서 에디터 초기화가 끝난 뒤 테스트를 시작해 해결했다. 런타임 오류 감시는 유지하며 어떤 게임 오류도 무시하지 않는다. 검증 전용 진입점은 원본 프로젝트에 추가하지 않았다.

컴퓨터 화면 캡처에서는 일부 작은 글꼴/윤곽선이 거칠게 보이는 현상이 남아 있어 완벽한 픽셀 재현으로 주장하지 않는다. 연결선의 좌표 조합을 수정해 실제 노드 사이 연결을 확인했다. Windows 배포용 실행 파일은 이번 작업에서 다시 빌드하지 않았다.

## UI가 거칠게 보일 때

Game 뷰의 Low Resolution Aspect Ratios를 끄고 Full HD(1920×1080)를 선택합니다. Scale 1x에서 원본 화질을 비교합니다. 확인 과정은 [UI 화질 확인 기록](UI_QUALITY_CHECK.md)을 참고합니다.
